# Open-Cake on B300

[中文](../B300.md)

B300 has a separate `sm_103a` Target (compute capability 10.3). B200 keeps
`sm_100a`. This first slice supports Python Schedule authoring and Triton for
three existing operators. CuTe, checked CUDA assets, historical direct-CUDA
studies and portfolio remain outside this B300 slice.

| Python starting point | Workload | Cases |
| --- | --- | --- |
| [RMSNorm](../../examples/python/b300_rmsnorm.py) | [FP32 RMSNorm v2](../../contracts/workloads/rmsnorm-fp32-v2.json) | 6 |
| [GEMM+bias](../../examples/python/b300_gemm_bias.py) | [BF16/FP32 GEMM+bias v2](../../contracts/workloads/gemm-bias-bf16-fp32-v2.json) | 5 |
| [Indexed gather](../../examples/python/b300_indexed_gather.py) | [BF16 gather v2](../../contracts/workloads/indexed-gather-bf16-v2.json) | 4 |

These Python sources emit the same kernel body and compile/launch requirements
as their JSON baselines; provenance comments may differ. Gather indices share
one zipped domain, use rank-one INT32 registers and must have equal lengths.
The frontend retains their explicit read/dependency edges and infers `[J,D]`,
with no negative-index wrapping or changed masking. Buffer-index syntax is
currently load-only.

```python
from open_cake_ir.compiler import Compiler

compiler = Compiler.load(".", "compiler/revision.lock.json")
assessment = compiler.assess_file("examples/python/b300_rmsnorm.py")
lowering = compiler.lower(assessment)
print(lowering.target)  # sm_103a
```

[Baseline preparation](../../examples/paired_triton/prepare.py) still specializes
all cases using the selected v2 Workload, exporting JSON and Triton outside the
checkout. The [B300 Study template](../../contracts/studies/matched-search-triton-b300-optimization-template.json)
accepts `python_source`; its pending provider binding still requires live qualification.

Workload, Schedule, actual compilation, Candidate, manifest and device must agree
on the exact target. Device checks precede module load; function binary version
must then match that target. The Executor needs a separately verified B300 host
environment, including compiler, CUPTI timing and profiler files. Its historical
`b200-vN` namespace is an opaque software id, not hardware qualification.

B300 inherits no B200 occupancy, peak or cost calibration. Persistent grids are
refused before emission when the Target has no SM count. Static/CPU evidence
does not establish GPU correctness, timing, agent benefit or framework acceptance.
See [ADR 0053](../adr/0053-b300-is-an-exact-target.md) for the design and release gates.
