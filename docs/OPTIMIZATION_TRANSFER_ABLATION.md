# 方法附录：优化知识迁移的消融设计

[机制正文](OPTIMIZATION_TRANSFER.md) · [技术报告](README.md)

**状态：实验设计，尚未执行。** 本文规定处理变量、对照和估计量；实际模型、任务清单、
精确目标、阈值和预算由执行前的 Study 固定，执行绑定进入 CampaignLock。
现有工程经验材料及 `artifact_optimization_only` 结果不能直接充当下面的科学实验单元。

## 1. 研究对象与冻结边界

研究对象是**向目标平台 Agent 额外提供的经验与工具**，不是模型预训练知识的增减。
机制先在源平台形成，随后在目标开发集适配，最后在冻结的目标测试集验证迁移。
首个研究可固定一个机制与一个源/目标组合，如 NVIDIA/Triton 到 AMD/Triton；跨 lowering
迁移作为独立后继，避免一开始同时改变硬件、编写环境和后端覆盖。

- 发现集、目标适配集、目标测试集按工作负载/算子族划分；同一模板的改名副本不算独立任务。
  同族未见形状与未见算子族分别报告，不混称泛化。迁移材料和 pass 在测试集运行前冻结。
- 每个目标先固定可运行的共同基线、语义与精度、oracle、容差、硬件、工具链、计时范围及
  测量质量门。缺少可表达性或可靠计时的案例列为覆盖缺口；测试开始后不因结果不好删除案例。
- 如需新增 IR 或 lowering，先完成该能力的独立验收，再让四组共享同一后继 Compiler。
  后端升级带来的基线变化单列，不能归给经验迁移。
- 测试期间不新增机制、改 pass 或放宽 guard。Agent 仍可在允许的候选参数与已有语义空间内搜索；
  新发现进入后继研究，不反馈给本轮其他组。

## 2. 两个处理变量

| 组别 | E：机制材料 | P：变换调用 | Agent 可进行的工作 |
|---|---|---|---|
| E0P0 | 不提供 | 不开放 | 使用共同 IR、工具与反馈自行构造候选 |
| E1P0 | 提供 | 不开放 | 阅读机制与反例，自行实现相同或不同的改写 |
| E0P1 | 不提供额外说明 | 开放 | 使用 pass 的最小接口合同，选择是否调用及其参数 |
| E1P1 | 提供 | 开放 | 结合机制材料与 pass 调用构造候选 |

**E 的内容**固定为机制解释、适用与不适用条件、源平台观察及反例。它不提供目标测试任务的
优化实现、最佳参数或结果。源证据的定位供审计使用；未授权的源代码和产物不挂载给作者。
当前 OMOE `case/steps` 材料含低层实现，不能不经参考权限审查直接作为本研究的 E。

**P 的内容**是冻结的显式改写入口。最小合同包括输入/输出语义、参数域和必要前提，
因此 P1 本身也包含机制信息；E 的效果仅指在该接口之外增加说明与案例的效果。
P0 关闭该调用入口，但不能删去表达同一候选所需的基础 IR、算子或 lowering；手动发现与实现
该优化仍然允许。所有 pass 都必须由作者显式选择，不能在 `assess` 或 `lower` 中自动启用。

四组始终使用相同的类型/合法性检查、Target/backend 准入、外部正确性检查与测量门。
消融不关闭这些检查，也不关闭工作负载必需的数值约束。

## 3. 防止处理串扰

E 控制实际交付给作者的材料，P 控制实际可调用的工具，不能只靠提示词要求“不要使用”。
实验作者不继承维护 Agent 的会话、报告材料或项目级经验上下文。作者工作区与构建/评测
工作区隔离；P0 无法读取对应 pass 实现或借助另一命令调用它。
无法隔离时，该次运行不能作为 P0 证据。P1 的实现源码也不直接交付，避免额外的源码说明
变成未声明的第三种处理；返回的候选是该调用产生的作者产物。

按 `(目标、测试任务、重复编号)` 分块随机化执行顺序，每格至少 5 个独立 Run，
具体重复数在执行前冻结；共享输入种子，模型、reasoning effort、scaffold 和公共参考权限相同。
每个 Run 独立上下文、候选与 incumbent，不共享检索缓存、对话记忆或其他组生成的最优解。
工具链缓存采用统一预热约定，避免某一组替另一组支付编译冷启动成本。

各组使用相同的 token、编译/评测次数和墙钟上限，先到者停止；读取经验材料的 token、
pass 调用与验证开销都计入该 Run。例行日志记录材料引用、允许/拒绝的调用、实际用到的机制、
拒绝原因和候选去向，不能用分组标签推断处理确实发生。

## 4. 终点、失败与估计量

实验单元是独立 **Run**。主终点为：在共同预算内按冻结的选择规则提名一个固定候选，
经共同 Evaluation 的独立、新鲜确认收据证明其通过正确性、测量质量门，并达到事先声明的
相对本机基线提升阈值。搜索阶段的计时只用于选择，不能直接计为成功。四组预留相同的最终
确认预算；候选固定后不能依据确认结果换一个候选加试。阈值与确认协议在 Study 中预注册。

记 `p_ep` 为组别 E=e、P=p 中已确认成功 Run 数除以全部已分配 Run 数，
报告完整四格及以下预定对比：

- 额外材料主效应：`ΔE = [(p10 − p00) + (p11 − p01)] / 2`。
- 变换调用主效应：`ΔP = [(p01 − p00) + (p11 − p10)] / 2`。
- 交互效应：`ΔEP = p11 − p10 − p01 + p00`。

正式多任务研究按任务等权汇总，保留四组配对关系进行任务成组 bootstrap，报告 95% 区间；
重复运行不是额外的独立任务。正式任务数根据独立先导集在预注册时确定。任务不足的试点只报告
逐任务的 Run 计数、成功率和重复间变动，不给任务总体区间；单任务 bootstrap 不能估计跨任务
不确定性。单机制或单任务试点不能据此宣称跨算子族的泛化收益。

次终点报告首次正确候选的 token、编译/评测次数与时间，以及最终提名候选通过新鲜确认后的
本机相对性能。若研究另设中间确认检查点，检查点、提名次数和资源预算须对四组共同预注册，
首次合格优化的成本也只能取自同一确认协议；不能由搜索最小值反推该终点。未找到终点的成本
记为预算内未达到，保留右删失标记，不只平均成功运行。
无确认结果时性能记为缺失，不填零延迟；慢于基线但通过正确性与测量质量门的候选仍报告其比值。
搜索阶段的最好读数若展示，单列为描述性轨迹，不替代正式性能终点。
源码发现、目标适配和维护成本独立于目标搜索成本报告，避免把预先写好的 pass 当作零成本。

协议内错误、数值失败、无收益与预算耗尽保留在分母中。基础设施中断标为端点缺失，
主分析仅将其计为“未确认成功”，不能写成数值错误；同时报告完成数、缺失比例、已观测
子集的敏感性结果，以及将缺失全部视为失败/成功所得的成功率范围。不得事后挑选有利的重跑。
不同目标仅相对各自基线比较，不用 NVIDIA 的绝对延迟、成本模型或最优参数为其他目标赋分。

## 5. 接入现有框架

- **Finding / 原始证据**拥有机制、反例与来源；Compiler pass 拥有确定性改写；Lab 拥有
  材料选择、参数搜索和组别执行；目标事实仍归 Target 与 backend。报告和硬件页面仅作投影。
- **Study**拥有 E/P 处理、材料范围、分配、预算、缺失规则和估计量；CampaignLock 绑定
  具体源码、目标环境与作者材料。设计沿用 `matched_search` 的生命周期，不增加运行模式。
  但[当前配对合同](../src/open_cake_ir/lab/pairing.py)要求 `open_cake` 与一个已声明的比较环境，
  尚不能直接运行四个同路线处理组；E0P0 等是设计标签，不是现有 arm 名称。
- **待实现的最小接入**包括 Study 对同一作者路线多处理组的声明、分配与分析，以及作者材料
  和 pass 调用的受控交付、实际调用记录。它们需要经过协议扩展进入现有 Lab/Study 边界，
  不能将当前 Cake-vs-native 对照冒充 E/P 消融。本文件不提供虚构的 CLI 开关或可运行合同。
- 正式运行前，先用轻量验收确认 E0 不泄漏材料、P0 的调用被实际拒绝、P1 可显式调用，
  且四组通过同一正确性与测量路径。该验收不证明迁移收益；收益由上述冻结实验给出。
