# 在 B300 上使用 Open-Cake

[English](en/B300.md)

B300 使用独立的 `sm_103a` Target，计算能力为 10.3。B200 的 `sm_100a`
仍保留。第一版 B300 支持现有 Python Schedule 和 Triton 路线；CuTe、
checked CUDA assets、历史 direct-CUDA/portfolio 实验尚未扩展到 B300。

| 起点 | Workload | 用例数 |
| --- | --- | --- |
| [Python RMSNorm](../examples/python/b300_rmsnorm.py) | [FP32 RMSNorm v2](../contracts/workloads/rmsnorm-fp32-v2.json) | 6 |
| [Python GEMM+bias](../examples/python/b300_gemm_bias.py) | [BF16/FP32 GEMM+bias v2](../contracts/workloads/gemm-bias-bf16-fp32-v2.json) | 5 |
| [Python indexed gather](../examples/python/b300_indexed_gather.py) | [BF16 gather v2](../contracts/workloads/indexed-gather-bf16-v2.json) | 4 |

Python 起点与对应 JSON 基线生成相同的 kernel 主体及编译/启动参数。
注释中的来源信息可以不同。gather 的两个索引逐项配对，长度必须相同；
负索引不回绕，越界结果为正零。前端把索引寄存器加入 load 的显式读取和依赖，
结果形状为 `[J,D]`。这段索引语法当前只支持 load。

可以先进行静态检查和源码生成：

```python
from open_cake_ir.compiler import Compiler

compiler = Compiler.load(".", "compiler/revision.lock.json")
assessment = compiler.assess_file("examples/python/b300_rmsnorm.py")
lowering = compiler.lower(assessment)
print(lowering.target)  # sm_103a
```

各用例的 JSON/Triton 配对基线仍由
[prepare.py](../examples/paired_triton/prepare.py) 生成。选择对应 v2 Workload，
输出目录放在 checkout 外。Lab 的
[B300 实验模板](../contracts/studies/matched-search-triton-b300-optimization-template.json)
支持 `python_source` 提交，但模板中的 provider 仍待真实资格验证。

验证 IR 与原生 Triton 两个 authoring 环境时，使用
`tools/qualify_codex_provider.py --comparison-arm native_triton`，同时指定
`--maximum-candidates-per-turn`，并选择
`contracts/providers/codex-triton-optimization-output-schema-v1.json`。
这份 schema 对应 `--feature-policy closed_research`。
其余参数绑定实际 provider、模型、工作目录和外部证据目录。这个检查只验证
两个独立会话各自完成初始提交和续轮，以及 JSON 候选的完整归档；不编译或
运行候选，不证明 kernel 正确性或性能。默认比较对象仍为 `direct_cuda`。

Workload、Schedule、实际编译结果、Candidate、manifest 和设备必须使用同一
Target。加载模块前检查设备，加载后检查 CUDA 函数的 binary version；B200 与
B300 混用会被拒绝。Python 环境、Triton、CUPTI、计时工具和 profiler 需要新的
B300 主机绑定。Executor 的历史 `b200-vN` 名称只是软件版本命名，不是硬件证明。

当前 B300 Target 不继承 B200 的 occupancy、peak 或成本校准。缺少 SM 数量时，
persistent grid 会在 lowering 前明确拒绝。静态检查、源码等价和 CPU 测试不等于
GPU 正确性、性能、agent 优势或框架端到端验收；这些结论分别需要对应实验证据。

设计和发布边界见 [ADR 0053](adr/0053-b300-is-an-exact-target.md)。
