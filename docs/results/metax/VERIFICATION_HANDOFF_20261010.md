# C550 验证状态与下一步 Compiler 工作

本页汇总已有实验的证据范围。独立 Bench 固定为 `ababa4c0`；实验集成是
`b2180ca2`（[PR #402](https://github.com/qhy991/open-cake-ir/pull/402)），
不代表这些改动已经进入 `metax` 或 `main`。后续组件分别固定源码，不继承整套资格。

## 哪些经验值得内化到 Compiler

| 发现 | 应归属的改进 | 晋升前必须补的证据 |
|---|---|---|
| 输出分片、执行组数量和 cast 位置会共同影响性能 | 完整改写归 Compiler；目标参数选择归 Lab | 每次只改变一个机制，保留数值语义和反例；来源候选收益不当作 pass 收益 |
| singleton 归约和存储承诺可能在 lowering 时失真 | IR 形状语义、Verifier 和 lowering 一起修正 | 精确保留候选的复播；合法 singleton、指针误作数值、shared/register 不一致分别测试 |
| RoPE 的原参考与替换实现存在舍入差异 | 带适用域的数值变换与目标指令资格 | 原比较器、边界输入、目标设备；当前 TF32 仍未准入，不能通过放宽容差解决 |
| Program 性能受主机提交空隙影响 | Evaluation 的测量协议 | 新协议、新基线、同实现控制及独立 profile；不记作 Compiler 加速 |
| 未排空设备工作时清理对象存在风险 | worker 和资源生命周期 | 故障路径保持诊断、拒绝收据、禁止过早释放；与正常清理分开验证 |

Compiler 修改先使用开发任务与 Findings 验证，冻结版本后再进入独立 Bench。
一个失败记录只能建立具体缺口；不能由报错数量推断 IR 不可表达或硬件不支持。

## 有限资源下的完成顺序

1. 保存原始输入、候选、逐轮事件、确认结果、源码提交和工具链来源。副本保留原结果，
   不恢复权限来制造 custody，也不自动继承设备资格。
2. 优先补齐已可编译任务的原始正确性。各题使用原 16×10 连续输入序列；失败留下
   最小复现与归属，不更改 oracle 或数值策略。
3. 审查公共 worker 修复，再把排队计时组件接入独立后继；冻结新测量协议并单独资格化。
4. 只有全部门槛通过，才启动完整的三小时优化。每题仍为 9720 秒搜索与确认，加
   1080 秒整题复验。时间不足时保留未启动状态，不能截短后仍报告三小时实验。
5. 每项发现记录 disposition：Compiler、Verifier、lowering、Lab、Evaluation，或
   `No promotion`。没有确认的新机制不强行新增 IR 原语。

## 恢复工作需要什么

公开仓库保留代码、合同、Findings 和上述 PR。私有存档另保留原始实验及环境记录。
恢复时先验证源码和数据可读，再重新核对精确 Target、ABI、工具链、数值策略、
设备序号、PCI 与锁绑定。容器镜像或外部对象缺失必须明确记录，文件副本不是完整运行环境。

本页不发布原始数据、凭据、主机地址或内部操作安排。
