## 本轮补齐的两项设备结果

在相同固定源码、工具链与数值策略下，RoPE 和 Gate-Up 各首次完成最终版本的
原始 16×10 检查。RoPE 为 160 次 native 调用；Gate-Up 每次完整调用含三个阶段，
共 480 次 native 调用。两题均通过原比较器，输入保持不变、模块关闭、worker 退出、
物理锁释放。没有计时、provider 回合或优化 Run。

因此，最终集成版本目前具有原始完整正确性证据的任务为 **3/10**：RMSNorm、RoPE、
Gate-Up。这三题共 480 次原始检查；其余七题保留待验状态。

## 已完成的 Compiler 机制复用

执行组选择已通过 [PR474](https://github.com/qhy991/open-cake-ir/pull/474) 进入 `metax`。
43 个明确候选的 215 项原正确性检查通过；1/2/4/8 组可由显式变换生成，16 组仍拒绝。
适用条件、反例及资源记录见[执行组资格](WIDTH_QUALIFICATION_20261010.md)。

FP32 NT contraction→IEEE MMA 的独立 [PR478](https://github.com/qhy991/open-cake-ir/pull/478)
已进入 `metax`，完成 20 项原正确性检查。原实现及三个改写候选保留原误差标准；组合版本通过 60 项合同，
实际编译输入与受测版本一致。它与旧 Bench 的 `b2180ca2` 是不同源码和不同证据范围，
不能把这些开发任务计入 3/10 的独立 Bench 覆盖。两项复用均没有新计时结果。

## 哪些经验值得内化到 Compiler

| 发现 | 应归属的改进 | 晋升前必须补的证据 |
|---|---|---|
| 输出分片、执行组数量和 cast 位置会共同影响性能 | 完整改写归 Compiler；目标参数选择归 Lab | 每次只改变一个机制，保留数值语义和反例；来源候选收益不当作 pass 收益 |
| singleton 归约和存储承诺可能在 lowering 时失真 | IR 形状语义、Verifier 和 lowering 一起修正 | 精确保留候选的复播；合法 singleton、指针误作数值、shared/register 不一致分别测试 |
| RoPE 的原参考与替换实现存在舍入差异 | 带适用域的数值变换与目标指令资格 | 原比较器、边界输入、目标设备；当前 TF32 仍未准入，不能通过放宽容差解决 |
| Program 性能受主机提交空隙影响 | Evaluation 的测量协议 | 新协议、新基线、同实现控制及独立 profile；不记作 Compiler 加速 |
| 未排空设备工作时清理对象存在风险 | worker 和资源生命周期 | 故障路径保持诊断、拒绝收据、禁止过早释放；与正常清理分开验证 |

Compiler 修改先使用开发任务与 Findings 验证，冻结版本后再进入独立 Bench。
一个失败记录只能建立具体缺口；不能由报错数量推断 IR 不可表达或硬件不支持。

## 有限资源下的完成顺序

1. 保留支持结论的必要原收据、候选、事件、源码差异和工具链来源。公开源码引用 GitHub，
   已有本地证据引用原位置；不复制完整仓库、镜像、缓存或重复的大型实验目录。精简材料
   明确省略的范围，不声称是完整 EvidenceStore，不恢复权限来制造 custody 或设备资格。
2. 优先补齐已可编译任务的原始正确性。各题使用原 16×10 连续输入序列；失败留下
   最小复现与归属，不更改 oracle 或数值策略。
3. 公共 worker 后继已经独立复核；先完成共享层集成，再把真实排空失败检测和排队计时
   组件接入独立后继，冻结新测量协议并单独资格化。两次 Mac custody 环境错误保留，
   Linux 通过不自动资格化该 Mac 环境。
4. 只有全部门槛通过，才启动完整的三小时优化。每题仍为 9720 秒搜索与确认，加
   1080 秒整题复验。时间不足时保留未启动状态，不能截短后仍报告三小时实验。
5. 每项发现记录 disposition：Compiler、Verifier、lowering、Lab、Evaluation，或
   `No promotion`。没有确认的新机制不强行新增 IR 原语。
