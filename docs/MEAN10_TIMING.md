# 十次正式执行的均值计时设计

[共同研究主题](RESEARCH_AGENDA.md) · [实验流程](wiki/experiments.md) · [MetaX 迭代](METAX_COMPILER_EVOLUTION.md)

**状态：2026-10-06 经用户同意的后继设计；尚未完成 C550 的新协议设备验收。**
本页拥有这项设计的统计口径与迁移条件。发布设计不改变 launcher 默认值，不改判历史结果，
也不为任何目标授予新的计时或完整 Program 资格。

## 1. 主指标与样本单位

每次搜索评测中，基线和候选各保留 **10 个正式设备计时样本**：

\[
\bar t = \frac{1}{10}\sum_{i=1}^{10}t_i,\qquad
\text{speedup}=\bar t_{\mathrm{baseline}}/\bar t_{\mathrm{candidate}}.
\]

- 十次是每个实现的**总正式样本数**，不是十组各十次，也不是十个 Agent Run。
- 预热次数在执行前固定并另计；预热、编译、输入准备、正确性检查不混入该均值。
- 一次样本测量目标合同指定的计算区间。单 dispatch 与完整多阶段 Program 分别声明。
  多 dispatch 编码在一个区间内时，须说明样本单位，不能把它悄悄当作十个独立样本。
- 均值是搜索排序、独立确认、加速比、incumbent 与结果展示的主指标。中位数可作诊断，
  不能仍用中位数选候选、最后只把显示名称改成 mean。
- 保存十个原始值及其均值、总体标准差、CV、最小值和最大值。总体标准差使用同一批十个值；
  不用单个采样块的 CV 冒充全部十次的波动。

正确性继续使用各任务原有的输入分布、oracle、容差与输出检查。c550-bench 每题的
16 个原始 workload 和每 workload 10 轮新输入，与这里的十次计时是不同层次。

## 2. 基线与候选的共同条件

两者使用相同设备、输入、工具链、计时区间和 cache-reset 协议，遵守相同 GPU 分配与隔离规则。
先冻结测量顺序，平衡基线／候选的先后位置；不让一方承担当次编译或冷启动成本。
不同硬件可以使用自己的已验收计时器，但共同使用明确的均值口径，报告各自区间与覆盖限制。

现有配对模型可表达的拟议绑定如下，实施时仍须验证实际采样与调用计数：

| 字段／安排 | 后继取值或含义 |
|---|---|
| `statistic` | `mean` |
| `pair_order` | 第一块 candidate→baseline，第二块 baseline→candidate |
| `samples_per_cohort` | 每臂每块 5 个；两块合计每臂 10 个 |
| `maximum_cv` | `null`：波动只作诊断 |
| `maximum_relative_iqr` | 若该目标声明此字段，也不启用额外波动硬门 |
| `required_pair_wins` | `0`：块胜数仅作诊断，不套用旧的 9/10 门 |
| `materiality_ratio` | 由任务／研究明确固定；本设计不自动改变提升阈值 |
| `route_calls_per_cohort` | 由目标既有预热／校准／正式执行合同推导，不设全平台常数 |

例如，现有 MACA 合同要求每块目标 route 调用数为 `11 + samples_per_cohort`，上述绑定为 16。
它只说明既有字段怎样表达十次正式采样，不证明这条后继设备路线已经验收。采样块不是
新的研究重复；两块各自的均值可诊断顺序影响，不能据两块胜负宣称统计显著。

## 3. 波动诊断与硬性有效性分开

对于采用本设计的新开发 Run，**不再以固定 CV > 5% 自动否决性能读数**。CV 和原始样本仍保留，
高波动提示结果不确定；一次均值或一次新鲜确认不构成统计显著性证明。接近噪声幅度的小收益
应标注不确定性。正式研究的主要终点与统计推断另行预注册。
报告须明确 `dispersion_gate=diagnostic_only`；没有启用波动硬门不能被描述为已证明稳定。

以下条件仍然硬拒绝，失败时整次配对评测没有性能分数：

- 数值、输出、输入保持或任务声明的安全条件失败。
- 正式样本数量不符、样本缺失、非有限值或非正耗时。
- 原始时间戳零宽、倒序或与声明区间不一致。
- 启动身份、目标、stream、cache reset、设备活动或采集覆盖违反目标合同。

保留完整失败记录，不删异常样本后补采凑到十个，不循环重跑直到结果好看，也不把失败填成零延迟。
统计口径变化不能放宽上述采集有效性条件。计时器或采样区间的替换是另一项需独立验收的设计。

## 4. 搜索、提名与独立确认

搜索时使用十样本均值选择候选。提名后固定产物，对基线和候选分别重新采集十个正式样本，
通过相同正确性与有效性条件后报告确认均值和加速比。不能依据确认结果换候选加试。
固定基线身份保持；“新鲜”指新的输入／测量实例按原合同产生，不是替换基线实现。

独立确认的预算包含在该 Run 的三小时总预算内。作者重复次数属于实验设计，不由计时样本数决定。
当前开发计划每个已准入任务一个独立优化 Run；c550-bench 留到 Compiler 后继冻结后测试。
后续 C0/C1 外部对照也须共同绑定已验收的统计策略；完整 Program 未取得计时资格时只报告
其正确性与覆盖，不用单个 stage 的均值替代完整计算。
不能把新的单次工程 Run 自动标记为原有正式 E/P Study。

## 6. 后继验收与迁移

1. 在独立后继提交接通明确的十次采样绑定，不修改冻结 Run、收据或旧策略。
2. 复用现有协议、Evaluator、派生指标与 Run 入口；所有读取延时的位置遵守 `statistic`。
3. 软件验收覆盖：总样本数恰为每臂十个；均值与中位数不同的样本；顺序与调用数；
   零值／缺样／非法原始活动拒绝；高 CV 仅诊断；旧中位数收据按原含义回放。
4. 在精确设备上验证原始样本来源、预热与 cache reset；完成同产物 A/A、正确性和 profiler。
   A/A 检查须有预先固定的接受与停止规则，不按观察结果临时选择界限。
5. 新采集不得产生未解释的零宽／倒序／身份异常。某一次 A/A 通过只支持该控制范围，
   不能覆盖此前失败或证明所有短 kernel 均稳定。
6. 完成所需验收后，新的 RunSpecification 显式绑定新版本和新策略。验证不通过时保留失败，
   在另一个后继版本重新验收；不临时修环境后沿用旧检查。

既有预算口径、旧中位数结果、CV 拒绝和协议故障均保持原记录。若展示旧样本的均值，须标成
事后描述性重分析，不能改写它们当时的资格、晋升或科学终点。
