# 共同研究主题与硬件实验约定

[项目首页](../README.md) · [技术报告](README.md) · [English](en/RESEARCH_AGENDA.md)

**open-cake-ir 研究如何把优化发现整理为带条件的可执行机制，在保留目标硬件特化能力的同时，降低后续任务的搜索与适配成本。** Compiler 是产品核心：它拥有 Program、Schedule、合法性分析、确定性改写和 lowering。Lab 组织作者、材料、预算和研究分组；独立 Evaluation 与 Evidence 决定候选的正确性、测量资格和结论范围。

本页维护共同研究问题、贡献边界和各硬件分支的实验方向。[路线](ROADMAP.md)安排推进顺序，[迁移设计](OPTIMIZATION_TRANSFER.md)解释机制，[E/P 协议](OPTIMIZATION_TRANSFER_ABLATION.md)拥有材料与变换权限的具体统计约定。各平台沿用这些定义，结果仍由原始记录和各自的发布数据维护。

## 主问题与研究假设

**在相同任务语义、参考权限和声明预算下，哪些优化决策适合由 Agent 自由探索，哪些适合固化为带条件的改写；这种分工能否减少目标侧重复搜索，并保持对强实现的性能竞争力？**

| 假设 | 主要比较 | 需要报告的结果 |
|---|---|---|
| 表示与工具改善有限预算搜索 | Cake 与原生 DSL，提供同源材料、语义等效工具及公共评测 | 独立确认的性能、达到预定终点的成本、表达覆盖与强实现差距 |
| 来源经验及可执行化有额外价值 | 通用说明与来源机制材料；另按 E/P 协议区分说明与调用权 | 成功率、搜索成本、负迁移；来源发现和目标适配成本另列 |
| 系统演进改善后续优化 | 固定候选集上的新旧诊断；后继版本上的全新搜索 | 建模范围、误拒/漏检、未覆盖项，以及未参与修复的任务结果 |

这些是待检验的假设。平台接入、一次本机加速、某个 pass 可运行，分别提供局部证据；它们不能直接替代上述对照。

## 一条经验应当保留什么

一条机制包括前后程序、优化意图、适用条件、可调目标决策、来源证据和反例。沿用 Findings、Compiler pass、Lab 材料与原始结果的职责，不新增平行的经验账本。

- **语义条件**：消费者、别名、依赖、同步和数值舍入是否允许改写。
- **目标实现条件**：精确 Target、后端、工具链、加载接口及运行环境能否兑现。
- **收益假设**：在该形状和资源分配下是否值得采用；以目标实测确认。

静态检查只在其已建模域内阻止非法候选。未支持、未建模、未取得资格与已证实错误分别记录；收益估计用于排序，不伪装成合法性门。两个各自合法的 IR 不自动等价；可信变换构造、模型内证明和设备测试应注明各自保证。

优先研究 tiling、归约数据与执行者分工、存储复用，以及具备完整验收条件后的融合。只改变执行宽度可作为简单对照；多处关联修改用于检验可执行化的价值。目标采用具体存储、访问和执行承诺，保持现有“不引入 layout 代数”的边界。

## 表示、lowering 和搜索策略分开比较

| 比较轴 | 共同边界 | 解释范围 |
|---|---|---|
| Cake 与原生 DSL＋工具 | 同任务、目标、资料、合理语义能力、下游工具链与公共评测 | 表示与诊断组合的增量；若内部共用 Cake 引擎，明确是作者接口对照 |
| 原生 DSL 与直接低层生成 | 同执行合同；明确 grid、线程数、常量和 ABI 的可变范围 | lowering 路径与指令选择自由度；另报各自完整能力 |
| 非 LLM 与 Agent 选择 | 同动作集合、参数域和评测预算 | 选择策略的增量；允许任意写代码的 Agent 另作系统比较 |
| 同一目标上的 E/P 四组 | 共用 IR、Compiler、后端能力、oracle 和质量门 | 额外经验说明与变换调用权；P 的最小接口本身也包含知识 |

直接低层路线须先通过目标侧作者、工具链、加载和测量准入。`native_cuda` 是从 Schedule 生成代码的后端，不能据其名字推导任意 PTX 作者入口已经具备资格。NVIDIA PTX 实验也不替代 MetaX、Hygon 或其他目标的原生路线验收。

共同能力子集用于解释因素，完整合理能力用于检查实际性能空间。两者分别报告。不同模型、参考起点、计时协议或预算的公开数字不横向排名；不显著的差异也不自动等于已经证明等效。

## 原生发现如何沉淀

IR 保持默认开发接口。具体优化假设暴露表达或 lowering 缺口时，保留候选和诊断，可在已取得资格的路线建立**独立原生工程 Run**。它沿用同一 Workload、精确 Target、oracle 和测量要求，声明预算、继承材料及参考访问。

发现按责任层晋升：时机和选参进入 Lab；可复用改写进入 Compiler pass；兑现缺口进入 lowering；可建模的非法行为进入 Verifier；真实表达缺口才扩展 primitive、类型、效应和分析。审查与验证完成后，后继提交用于新 Run。`No promotion` 是有效结论。

冻结 Run 内不切换路线、不注入新经验、不修改 Compiler。新 Run 不消除已有参考访问。原生成绩与重新表达后的成绩分别验收；不把任意低层代码封成不透明节点后继承原有 IR 保证。人工提炼与自主提炼分开记录，发现、实现、审查和维护成本都属于研究成本。

## 各硬件分支怎样围绕同一主题工作

各分支选择可可靠评测的任务，回答同一主问题；不要求每个分支重复整套实验。下表是优先问题，不宣称相关路线已全部具备资格。任何平台都可以成为经验来源或迁移目标。

| 维护分支 | 优先检验的技术差异 | 对共同主题的贡献 |
|---|---|---|
| `nvidia` | 显式存储/同步、不同 lowering 与合格低层生成 | 提供结构性发现、强原生对照及检查覆盖反例 |
| `metax` | 联动分块、产物资源需求、驱动限制和计时资格 | 检验机制如何在目标约束下实例化；区分优化与执行/测量缺口 |
| `dcu` | 目标侧分块重选、数值行为及寄存器/scratch 观察 | 检验来源条件是否比通用知识更有信息量，保留负迁移 |
| `amd` | 各精确目标的执行宽度、资源和工具链差异 | 检验同类机制的目标重选，不沿用其他厂商或型号的校准 |
| `metal` | threadgroup 分工、存储关系与表达/测量覆盖 | 检验机制可复用部分与需要新实现的部分 |
| `main` | 公共表示、规则、方法与结果汇总 | 汇集经验证的共享能力，维护比较口径，不替平台宣布资格 |

每个新实验在现有计划或 Run/Study 输入中说明：所回答的假设、机制与精确任务、对照、参考权限、预算、测量合同和停止/确认规则。工程运行声明其产物范围；科学对照在执行前冻结分组与估计量。这些是写作与设计要求，不增加 Run schema、Study kind 或第二套执行器。

**新优化 Run 的默认预算为每项 3 小时，最终确认包含在该预算内。** 启动时显式绑定 `wall_time_seconds=10800`，并声明确认预留、编译/评测等上限；不能依赖某个 launcher 的历史默认值。专项准入探针另设有界预算。研究若改变预算，须在执行前对各组一致声明；既有冻结 Run 保持原规则。轮次、墙钟、token 和设备用量分别记账，排队及 CPU 准备成本不事后删除。

发现集、目标适配集、目标测试集分开。已经参与机制或参数选择的任务属于开发证据；未见形状、未见算子族和新硬件分别解释。同一形状的多次 Run 和一次 Run 的计时样本都不是新增独立任务。处理按卡位和时间分块；保留所有已分配 Run、失败和未达到终点的结果。

## 与相关路线的关系

| 相关工作 | 需要承认的已有机制 | 本项目需要进一步检验的增量 |
|---|---|---|
| [CAKE](https://arxiv.org/abs/2608.12629v1)、[TIRx Harness](https://github.com/mlc-ai/TIRx-harness) | Agent 编写接口、编译分析、反馈与优化流程 | 条件化经验及目标适配如何改变后续搜索 |
| [Exo 2](https://arxiv.org/abs/2411.07211v4)、[MLIR Transform](https://mlir.llvm.org/docs/Dialects/Transform/) | 可调用、组合和扩展的调度/编译变换 | 具体机制的提炼、边界和目标重新实例化 |
| [AutoTVM](https://arxiv.org/abs/1805.08166)、[MetaSchedule](https://arxiv.org/abs/2205.13603) | 调优、成本模型和可扩展搜索空间 | Agent 对结构决策的增量及其成本 |
| [AKG kernel Agent](https://arxiv.org/html/2512.23424v1) | 优化 sketch 与多 DSL 实现分工 | 确定性执行与目标诊断能否减少关联修改损耗 |
| [KernelBlaster](https://arxiv.org/abs/2602.14293)、[AccelOpt](https://arxiv.org/abs/2511.15915) | 优化经验形成和后续利用 | 可执行经验相对文本、案例和代码检索的收益 |
| [AI as a Compiler](https://arxiv.org/html/2609.36800v1) | 固定 Triton 执行合同下直接生成 PTX | 表示收益与 lowering 自由度分别比较，研究原生发现的后续复用 |

AI lowering 的候选来自既有源码和固定执行合同；其参考信息、模型和预算需要与对照匹配。该论文的最佳候选比较提示验证覆盖可能限制搜索结果，但不等于某一验证子集的理论性能上界。[原 Volta](https://arxiv.org/abs/2511.12638v3) 的模型内保证与新增扩展的保证分开解释。NVIDIA 的 [`ptxas`](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#syntax) 仍承担优化与汇编。

本项目以这些工作作为基础和对照。多后端、经验库、Agent 或双循环的组合不单独构成新颖性结论。贡献应对应明确机制、受控证据、维护成本和适用边界。
