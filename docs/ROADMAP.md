# 研究路线与实验优先级

[项目首页](../README.md) · [共同研究主题](RESEARCH_AGENDA.md) · [技术报告](README.md)

研究围绕一个问题推进：**把优化发现变成带条件的可执行机制，能否在保留目标特化和性能竞争力的同时，减少后续搜索与适配成本？** 各硬件分支采用[共同约定](RESEARCH_AGENDA.md#各硬件分支怎样围绕同一主题工作)，按自身已经取得资格的路线贡献证据。

| 阶段 | 工作与对照 | 进入下一阶段的依据 |
|---|---|---|
| 可靠的目标基线 | 固定 Workload、精确 Target、可启动基线、oracle、计时与 profiler；定位表达、产物资源和测量拒绝 | 能在声明范围内可靠比较；保留无法比较的覆盖项 |
| 搜索策略与动作粒度 | 在同动作集合和参数域内比较枚举/随机选择与 Agent；再单列自由编写程序 | 确定 Agent 对哪些结构决策有增量，避免把普通调参成本当成必要成本 |
| 表示与诊断增量 | Cake 与原生 DSL＋同源材料＋语义等效工具；共同子集和完整能力分别报告 | 在有限预算、覆盖和强实现差距上得到可解释的正、负或不确定结果 |
| 来源经验与目标适配 | 冻结发现/适配/测试划分；比较通用与来源机制材料，并按 E/P 协议控制调用权 | 确认来源信息和可执行化各自的作用，报告负迁移与构建成本 |
| 原生发现与系统后继 | 独立合格原生 Run；按职责提炼机制，审查后进入后继提交 | 固定候选集验证诊断变化，再用未参与修复的任务测试搜索效果；允许 No promotion |
| 累积复用与应用 | 静态库/增量库顺序任务对照；强种子再接入完整 Program、模型或服务 | 计入维护成本，验证尾部、动态形状、dispatch/fallback 和端到端收益 |

先导可以从一个可靠目标、一类机制开始。扩展平台应增加新的技术差异，而不是只增加品牌数量；无需把整张表做成一次巨大的全因子实验。

## 当前案例怎样服务于主线

- 简单执行宽度调整作为基础对照；复杂实现本身不自动形成研究新意。
- K/N 分块涉及循环、累加、访问和输出分配，可作为联动改写主例。明确哪些决定可共享，哪些必须在目标重选。
- 保留 BF16 中间舍入的融合可检验语义条件；完整基线与候选的共同评测资格先于性能研究。
- 归约数据与执行者分工可形成原生探索假设；具体存储和指令实现按目标验证。
- Megakernel、动态任务队列和多 GPU 通信在具体任务需要且前置路径可验证时引入。

## 现有结果与新实验

已有工程 Run 可用于复现、失败分析、机制选择和估计先导波动。若据此选择了方法或参数，这些任务就属于开发证据。原始实验保留其冻结的规则和解释；不能重标成新消融组或未见测试。

新优化 Run 按共同约定显式绑定三小时总预算，并保留最终确认资源。固定时间不等于固定 token 或设备用量。独立确认、失败分母、卡位/时间分块和维护成本随研究计划一起冻结。

各平台结果与代码资格见[状态](../reports/current/STATUS.md)和[结果索引](RESULTS.md)。本路线规定后续问题，不改变历史成绩，也不宣布各项接口或硬件已经完成验收。
