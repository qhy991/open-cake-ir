# 怎样读结果，也怎样排错

**先问这一步检查了什么，再看它是否通过。**
一个绿色状态只对自己的检查范围负责。

[返回 Wiki](README.md) · [正式证据术语](../GLOSSARY.md#evidence-strength-and-scope)

## 从计划到实际运行

| 看到的结果 | 可以说什么 | 还缺什么 |
| --- | --- | --- |
| `accepted=true` | 计划通过已建模的结构与语义规则 | 后端是否能生成、GPU 是否能跑 |
| `lowering_eligible=true` | 当前后端允许生成源码 | 工具链编译和运行 |
| `generated=true` | 源码由计划生成 | 正确性与测量 |
| `generated=false` | 使用核验过的固定源码路线 | 不能声称任意新计划都能生成它 |
| Corpus `passed=true` | 正例和反例的表现都符合预期 | GPU 答案正确 |
| GPU correctness 通过 | 固定输入、输出和状态要求通过对应检查 | 稳定计时、其他形状和完整模型效果 |
| 测量被接受 | 这组样本符合当前计时协议 | 其他部署或更大范围的结论 |

源码生成不会自动申请 GPU。不同执行工具的 JSON 字段可能不同，要一起读任务合同与对应 receipt。

## 两个最容易混淆的标志

`accepted` 与 `lowering_eligible` 是独立信息。
例如一个计划的结构合法，但后端尚不支持它，就可能“接受：是，允许生成：否”。
`assess` 的退出码只表示是否接受，不能单凭退出码判断能否继续生成或运行。

中文模式下，文件不存在、JSON 无法读取、版本不匹配或输出文件已存在时，会显示“命令未完成”，
并返回非零退出码。先处理这类输入问题，再看计划本身的诊断。

中文输出中的诊断也分三种：

- **阻止接受：** 当前计划违反规则，应先改对应位置。
- **阻止生成：** 结构可能成立，但所选生成方式不支持它。
- **提示：** 提供分析信息，本条本身不阻止接受或生成。

不要把所有 Finding 都当成错误，也不要把提示当成测量成绩。

## 按位置处理诊断

`operations[3].parameters` 指操作列表里第 4 个操作的参数；`access_maps[2]` 指第 3 个访问说明。
先看位置、再看代码，默认 JSON 中还保留英文原文和完整分析。

| 常见代码或消息 | 普通话解释 | 下一步 |
| --- | --- | --- |
| `RESIDENCY_BOUND` | 声明的资源会限制并发工作数 | 区分静态声明与后端真实分配，不能直接推断速度 |
| `TARGET_UNSUPPORTED` | 当前发布不接受这个硬件目标 | 核对目标，不要偷偷换成另一张卡 |
| FMA arity / instruction 诊断 | 输入个数或数值指令合同不符合要求 | 对照完整 FMA 示例和原始诊断 |
| `STORE_EDGE_COUNT` | 写操作的读写边不完整或多余 | 检查每个值和目标是否正确连接 |
| `STATE_STORE_PROGRAM_OWNER` | 工作编号不能证明写入者拥有该状态位置 | 核对 ProgramMap 与状态维度 |
| `STATE_STORE_PROGRAM_AXIS_COVERAGE` | 状态写没有恰好覆盖所需工作坐标 | 核对是否遗漏或重复了轴 |
| `Executor Revision file ... differs` | 实际源码与固定 Executor 不同 | 回到对应完整版本，或走后继发布流程 |
| 来源对象或发布 lock 不匹配 | 历史任务正在混用另一版编译器 | 使用它固定的完整 Git 版本，不能只修改期望值 |

明确失败后保留记录，再修复新版本。不要覆盖旧 receipt，或靠改旧文件权限制造历史验收通过。

## 怎样读速度

假设相同条件下，基线需要 20 毫秒，候选需要 10 毫秒：

- 加速比是 `20 ÷ 10 = 2` 倍。
- 耗时减少 `50%`，不是减少 `100%`。

先看计时范围：一个 kernel、一整个算子、多个 kernel 的 Program，还是整次模型/服务请求。
前面一小块加速，后面的大部分不变，总体提升就可能很小。

再看重复样本。不能从基线取较慢的一次、候选取最快的一次来比较。
中位数是排序后位于中间的值，能少受极端值影响；但输入、机器和协议不同，即便都有中位数也不能直接比较。
置信区间表达估计的不确定范围，具体接受规则由 Study 提前约定。

## 为什么有时不能给结论

- **未运行：** 那一步没有执行。
- **unknown：** 记录不足以判断，如环境先失败或完整输出没有收齐。
- **invalid：** 当前证据或协议不能支持目标解释；不等于所有情况下算法都错。
- **正确但计时不稳定：** 保留正确性与测量质量的两个结论，不强行合成一个分数。
- **文件完整但没有 custody：** 字节可以复查，历史上谁能修改它却可能无法证明，因此不能自动升级为实验资格。

最后，报告应能指出标准答案、完整输入输出、固定版本和测量记录的位置。
找不到这些材料时，就保持较弱的结论。
