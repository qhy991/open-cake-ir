# 验收规则：做到什么，才可以进入下一步

[中文目录](README.md) · [英文原文](../ACCEPTANCE_GATES.md) · [术语表](../GLOSSARY.md)

“验收门槛”像考试的及格条件：先说明要查什么、用什么证据、没过就停止哪一步。本页解释稳定规则；某次实验有没有过，看它自己的报告。当前发布版看[自动状态页](../../reports/current/STATUS.md)。

## 1. 旧系统能恢复

要有干净且远端可取的旧版本、完整源码与证据清单、可独立恢复的历史备份、明确的秘密信息排除规则和足够磁盘。缺任何一项，就不能清理旧系统，也不能声称已经留下可恢复的前身。

## 2. 每件事只有一个负责者

Compiler 能独立使用；Lab 单向依赖它。编译、实验组织、评测、证据各有职责。Workload 定义题目，Study 定义实验。科学问题在开始前固定，非科学范围没有组间效果估计。候选改进和编译器升级分开；固定任务搜索与 portfolio 共用 Lab 路径；单产物优化是声明范围。

这些关系不清楚时，先修改架构决定，不能边跑边发明第二套负责者。

## 3. 独立编译器能工作

通过公开接口，一个正确计划应得到确定的检查结果和生成结果；一个对应反例应得到稳定、能定位的诊断。目标不匹配和缺少分析覆盖要明确报告。导入编译器不能顺带依赖 AI、GPU、Lab、评测或证据系统。失败归编译器修复。

## 4. 新编译器通过完整发布检查

检查全部正例和反例，固定目标、源码集合及预期，给出完整 Gate 差异，并由发布自动化之外的合格审查者批准。不能重生成预期让检查“自动正确”。缺少、错误或过期的批准会阻止发布。独立代理的进一步要求见 [ADR 0052](adr/0052-independent-agent-release-review.md)。

## 5. 两种写程序环境使用共同评测

两边都先封存可启动的产物，再进入相同的输入生成、标准答案、误差和测量规则。作者源码、生成源码、展开源码、PTX、CUBIN、SASS 要分清角色。

先判对，再计时或分析瓶颈；保存启动、路线、fallback 次数。搜索、确认、profiler 是不同评测记录。原始 profiler 数据要能重建摘要。答案正确与计时稳定分别判断。任何边界失败都会阻止依赖它的结论。

## 6. 证据能独立重放

写文件时只创建新内容，不沿链接写到保管范围之外；事件按类型和顺序追加，并由一个写入者负责。成功、失败、协议偏离都用同一种终态归档。新进程应能在不调用 AI、GPU、网络、不改 checkout 的情况下重建审计。

未知语义事件必须拒绝。文件完整性与保管可信性分开：文件齐全仍可能不允许据此生成结论。删除可重建报告后，应能从保留材料再次推导出它。

## 7. 不用 GPU，实验控制流程也得正确

通过 `preflight → execute → audit` 的公开接口检查：

- 执行前固定版本、环境、分组、重复尝试、预算、参考和推理强度；后续轮次保留同样约定。
- 每种结局都有归档。守规则却没有好候选，是观察到的负结果；provider、broker、保管或评测框架故障，是缺失数据。
- 完整性、保管、协议遵守、终点观察、分析纳入分别记录。不能用后来的候选补填早先检查点。
- 科学分析只回答预先声明的问题；系统资格和产物优化不产生组间估计。
- 后继代理接口使用不可变 `TASK.md`、`AGENTS.md`，只新增候选集合；每轮保存实际任务包。Ralph 在外部控制全部预算。任务、状态卡或回放包被改动时必须拒绝。
- 冻结的旧 Prompt 实验仍可按旧规则回放。测试必须实际调用接口，不能只查源码有没有某句话。

失败修复对应模块，不复制另一套带版本号的运行器。

## 8. 真实 AI 工具遵守封闭写作约定

在空工作区、不用 GPU，完成一次提交和一次继续更新，核对用量、沙箱、目录、会话、输出格式、功能策略和参考可见性。两种写程序环境使用相同 provider 条件。工具版本或行为变化，需要后继环境和新资格。传输通过不代表 GPU 或科学实验获准。

## 9. 默认 AI 功能仍只有一个候选提交者

只在工程产物优化范围允许 provider 默认功能。固定功能策略和事件词汇，记录辅助活动；主作者是唯一候选提交者，Lab 是唯一评测者。最终候选集合按安全的只读入规则接收。

有界实验可以让每个 Run 接收实测反馈，最多晋升一个确认合格产物；比较和科学字段必须不存在。观察到工具支持某功能，不等于允许它修改外部系统或自己测 GPU。

## 10. 小规模真实 GPU 路径接通

在 `system_qualification_only` 范围，每种环境各一个受限 Run，从干净 checkout 的准备、运行、终态封存到独立离线审计全部走通。每个 Run 至少有一份真实目标启动且正确性通过的记录；只编译不够。

可以说“系统路径通过资格检查”，不能汇合两组延迟，计算组间效果、估计或不确定性。

## 11. 切换源码负责位置可回退

要求远端可取源码、已发布 Compiler 与 Executor、零双写、完整旧材料清单、当前视图一致、磁盘检查、固定回退版本和仓库拥有者明确批准。旧树保留为只读恢复材料。

## 12. 科学结论满足它自己的问题

收齐预先安排的 Run Audit，按原计划处理纳入和缺失，取得完整终点、可用估计、不确定性和参考污染审计。缺证据时报告估计不可用，不能换新 Run、填补数值或扩大叙述来补救。

例如，“一个固定大小的算子更快”不能通过“任意形状”“模型前向”或“完整服务”的验收。每种结论都需要对应范围的证据。
