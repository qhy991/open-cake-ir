# 注意力调查：有些工作安排到运行时才知道

[中文目录](README.md) · [英文原始记录](../IR_COVERAGE_ATTENTION.md)

本页用中文解释原文的背景、决定和结论范围；逐项长表、精确来源及原始记录由链接中的原文负责。

**历史调查：2026-08-24 的 FlashInfer 源码。文中的缺口不是今天的能力结论。**

假设每个班人数不同，老师直到点名后才知道怎么分组。注意力的请求长度、KV 页和任务量也常在运行时才能确定。当时 Schedule 假定形状是固定整数、循环来自固定维度，这个差异不能只靠添加一个操作解决。

调查覆盖 SM80 FA2、SM90 FA3、协作持久运行器和 SM100 CUTLASS 路径。CTA 的工作可能由 CPU 成本模型分配、由 GPU 先生成任务表、由实测驻留决定拆分，甚至由每个 SM 的原子计数决定做 prefill 还是 decode。KV 访问还有页表、部分有效尾页和运行时除数。

九类突出缺口是设备任务表、不等长序列、Split-KV 与 LSE 合并、掩码改变工作次数、多阶段全网格协作、运行时选择算子、实测驻留反馈、生产与消费一起走空任务分支，以及跨 kernel 的 PDL。

在线 softmax 要跨块保留最大值和归一化量，重缩放输出，再完成跨线程归约；不能把单次乘法当整个协议。多角色也可能交替处理奇偶块，并把共享内存或 TMEM 当邮箱。GQA 的头号和 token 可以合并或分开映射，是性能选择。

调查提出两条可能路线：保持静态 Schedule、把动态分配放上层；或者改变类型系统来表达运行时范围。后继 [ADR 0006](adr/0006-candidate-sets-and-static-shapes.md) 选择静态形状，[0024](adr/0024-runtime-valid-extents-are-buffer-relations.md) 再补固定容量内有效前缀。原调查不证明完整注意力、调度或服务能力。
