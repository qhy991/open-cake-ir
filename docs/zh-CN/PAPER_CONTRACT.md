# 论文对照约定：论文说了什么，本项目证明了什么

[中文目录](README.md) · [英文原文、论文链接与完整对照表](../PAPER_CONTRACT.md)

本页解释原文固定的 CAKE 论文 v1。原文中的本地实现对照表是 **2026-08-25 的历史快照**，不描述今天的发布状态。后续论文版本或重新对照要另留记录；当前版本看[状态页](../../reports/current/STATUS.md)。

## 1. 先看结论来自哪里

| 标签 | 普通话解释 |
| --- | --- |
| `paper_reported` | 论文作者报告的结果，我们没有因此自动复现它 |
| `local_observed` | 本地保留的固定原始证据支持的观察 |
| `public_artifact_auditable` | 公开的产物允许独立核查 |
| `independent_reconstruction` | 本项目独立重建实现得到的结果 |
| `unknown` | 现有材料不够，暂时不知道 |

本项目独立实现部分研究思路。看到公开论文和结果，不能声称拿到了论文未公开的编译器源码。

## 2. 最小完整流程

```text
固定题目、机器、标准答案和参考范围
  → 给作者一种完整写程序环境
  → 检查计划格式、类型和硬件规则
  → 在有校准依据时排序
  → 编译，核对答案，测 GPU
  → 保存证据
       → 改下一个候选
       → 反复出现的问题形成编译器提案，经审查后发布下一版
```

静态检查是便宜的前置筛选，只检查已建模范围。真实正确性和速度仍靠外部参考及 GPU 测量。换硬件不能默默套用旧架构或旧校准。实验进行时编译器固定，升级发生在实验之间。

## 3. 比较的是完整环境

Cake 一边得到类型化 IR、定位诊断、分析和成本反馈，另一边直接写 CUDA/PTX。因此比较的是整套写作环境；如果想单独证明“IR 语法本身造成多少差异”，还需要专门拆分因素的实验。

独立实验单位是 Run，不是一个候选或一轮对话。科学 Study 必须预先说明比较目标、分配、终点、缺失处理和想估计的量。只检验系统接通的 Study 没有组间估计。只优化一个产物的 Study 可选确认合格候选，但它属于工程证据。

原文转述的论文条件是：GPT-5.6-sol、`xhigh`、B200、相同题目和参考政策，每组 3 次独立尝试，每次 80M provider token。Flash-KMeans 的固定输入为 `B=32, N=65536, K=1024, D=128`，BF16 输入、FP32 累加。论文报告基线 `0.938 ms`，预算末最佳结果的中位数为 Cake `1.144×`、直接 CUDA/PTX `0.928×` 基线速度。这些都属于 `paper_reported`，不是本次本地测量。

## 4. 五种问题需要五种证据

| 问题 | 最少需要的证据 |
| --- | --- |
| 相同条件下哪种写作环境更有效 | 独立重复、完整 token 轨迹、冻结因素一致、污染审计 |
| 没看目标实现能否找到好方案 | 实际参考可见性、正确性、固定终点、目标机器验证 |
| 能否重现或改进一个已知方案 | 固定参考、输入形状、正确性和相同计时规则 |
| 专用方案能否组成一个覆盖输入集合的库 | 预先声明范围、未用于调优的输入、边界与尾部、分发与拒绝覆盖、包含分发的计时 |
| 接入服务后是否改进应用 | 框架级正确性和不带 profiler 的端到端测量 |

先有强的固定形状种子，再研究多形状覆盖。不能用广覆盖掩盖一个错误或慢的种子。

## 5. 公开材料仍缺什么

原文列出公开的论文协议、汇总结果和 FlashInfer 中 KDA、TinyGEMM2、Alpha-MoE 的下游产物。它们可以作为已知实现复现或重新测量的对象，但不得进入“不能看实现”的 clean-start 环境。

原文所引用材料未给出完整的原编译器、IR 语义与规则、校准、提示和脚手架、原始搜索轨迹、全部 token 与计时收据、平台期定义、隔离实现、活动时间口径、精调基线版本和分发器细节。没有这些信息，就不能声称逐字节重建 CAKE，也不能把本地 8M 工程预算和论文 80M 直接相比。

实际给 AI 的编译器、语料、脚手架、记忆、诊断和每轮参考包都属于来源记录。如果编译器已根据同一道题的经验改进，实验还可研究这套工具的效果，但不能说它从没见过这类任务。

## 6. 怎样读 2026-08-25 的本地对照表

下面保留影响解释的全部主题，精确历史版本和证据引用见[原表](../PAPER_CONTRACT.md#local-implementation-alignment-snapshot-2026-08-25)。

| 主题 | 当时采用的解释边界 |
| --- | --- |
| 环境名称 | 使用 `cake_like`，说明是独立重建 |
| 推理强度 | 真实工具资格与冻结 Study 分开；不能把旧 `max` 实验改写成后来合格的 `xhigh` |
| 系统升级 | 实验内部不换编译器；实验之间走后继流程 |
| token | 本地按完整轮末的输入加输出计，缓存输入仍算输入；不能冒充论文的预算口径 |
| 时间 | 不用未知边界的 `active_evolve_time`；新计时要另命名并先固定包括哪些时间 |
| 科学终点 | 后继规则分开看合格率和合格后的延迟；旧实验保留旧规则 |
| 平台期 | 按已声明预算运行，平台期只作离线诊断 |
| 隔离 | 保存文件、工具、事件轨迹及实际参考包；缺失参考字节属于框架故障 |
| 参考访问 | Cake 给不完整接口，CUDA 给空主体；本地夹具不自动等于论文实验 |
| 计时 | 固定 B200 和环境，保留 CUPTI 冷 L2 原始样本 |
| 动态瓶颈分析 | 搜索后正确候选另做分析；原始 NCU 记录能复查；缺失 Run 仍使科学估计不可用 |
| 证据语义 | 后继关闭事件词汇范围，并分开归档完整性与文件保管；不重解释冻结记录 |
| 静态排序 | 当时的校准未通过原定错误率门槛，所以公开排序报告缺少覆盖 |
| 静态反馈 | Cake 得编译器诊断，CUDA 得 ptxas 资源反馈；按 Study 给正确候选有界 profiler 反馈 |
| 泛化 | 只描述当时固定的三形状 portfolio，不称任意形状或论文泛化 |

静态排序的旧全序试验错误率为 `35.95%`、`8.16%`。后来让并列截断放弃排序，检查每轮 `1,450` 个可决定子集并报告 `850` 个并列子集；两轮错误率 `5.73%`、`2.79%`，仍有一轮超过未变的 `5%` 门槛。因此“能测出结果”不等于“校准合格”。

旧 r42 实验虽然结束，预先声明的 150k 检查点估计仍不可用；不能用替补 Run 修复。它留下的种子后来进入单独固定的 r45 portfolio，两者不能合并。后者两个保留输入的分发计时边界不稳定，服务与论文泛化仍没有支持。
