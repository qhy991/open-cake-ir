**历史实现检查点：2026-09-04。后续正式发布见[发布审查](AKA_FMA_RELEASE_REVIEW_20260904.md)。**

隔离分支实现了三个同形 FP32 寄存器输入的 FMA，要求 `ptx.fma.rn.f32`，没有标量或广播字段。类型、数量、存储、形状、读写边、指令归属和后端目标不符都有定位拒绝。FMA 和 tanh 不能互借指令。

Triton 生成明确的非 FTZ、非饱和 RN-even PTX；嵌套 FMA 与另行舍入的乘法保持依赖。工作量每输出两次算术，已有生命周期分析计入三个输入，不增加物理寄存器或性能预测。

当时远端 CPU 检查：FMA 16 项包含在 208 项 draft 兼容测试中；另五项依赖旧发布身份的观察测试在原 v40 上通过，不能加成 v41 的 213 项通过。完整旧语料 `68/68` 未变。真实无 GPU 编译得到普通一条 FMA、嵌套两条 FMA 并保留单独乘法，分别产生 9,560 和 9,824 字节 cubin。

首次本地缺 jsonschema 没有加载测试，不计通过，也没临时安装掩盖。远端初次失败中旧二元覆盖断言已按三输入修正，旧锁测试明确分开。

四个新计划为普通 FMA、嵌套 FMA 两正例，以及少输入、错误指令两反例；此时仅为语料提案，尚未进 manifest，不能把 `68/68` 写成 `72/72`。旧 lock 与批准保留，发布流程按预期退出 3。

没有 GPU 数值、sanitizer、计时或性能，也没有完整 AKA 父项覆盖。一个独立任务显示结束但没返回审查内容，同样不能算独立同意。下一步是实质独立审查、单独采用四项、重建完整 Gate 再批准发布。
