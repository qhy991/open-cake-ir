# 历史迁移计划：把实验脚本集合变成编译器产品

[中文目录](README.md) · [英文原始记录](../MIGRATION_PLAN.md)

本页用中文解释原文的背景、决定和结论范围；逐项长表、精确来源及原始记录由链接中的原文负责。

**历史迁移材料。当前职责由[文档地图](CONTEXT-MAP.md)负责，本页不是今天的进度报告。**

目标是单向切换：新系统以独立 Compiler 为核心，Lab 使用它；旧系统只保留只读证据和回退依据。新实验只有一个写入者，不复制带 rXX/vN 名字的运行器。

| 旧材料 | 新的负责位置 |
| --- | --- |
| 正反计划及预期诊断 | Compiler Corpus |
| 硬件能力 | 精确 Target |
| 检查与生成行为 | Compiler Revision |
| 输入、oracle、容差 | Workload |
| 两边完整写作条件 | Authoring Environment 与 Study |
| 共同判对和计时 | Evaluation |
| 内容存储、事件与归档 | Evidence |
| 历史实现 | 固定 Git 版本 |
| 临时目录和缓存 | 不迁入正式源码；清理另需授权 |

## 当时的阶段
+
+先固定旧源码、证据清单和可恢复完整历史；从真实正反例提炼统一计划词汇。用一个完整正例及近似错误例走通独立 `assess → lower`，再用 TinyGEMM2 作为第二类真实题检验抽象。完整 Corpus 和外部审查之后才能冻结编译器。
+
+随后从封存可启动产物接通共同评测，把搜索与确认分开；证据既保留成功也保留失败，报告可重建。Lab 再分开题目与实验设计，先假 provider 零 GPU，后真实 provider 两轮无 GPU，最后每边一个受限 GPU Run 检验系统接通。
+
+切换阶段要锚定远端源码与发布身份，旧树只读，禁止双写，明确回退过程。原文记录当时切换完成；这句话属于那份快照，并不重新核验当前远端。之后固定种子进入独立 portfolio；服务因尚无完整框架端点仍在后面。
+
+单产物优化可以用 provider 默认功能，但没有科学比较资格。不得在清单和恢复依据未核验时删旧物；兼容只留给真实读入消费者。若需要第二套事实、版本化运行路径或没有真实用例的抽象才能迁移，就回到设计。
+
+原文的旧阶段、测试方法和版本命名保留作历史；今天的施工与发布应遵循当前仓库规则和后继 ADR。
