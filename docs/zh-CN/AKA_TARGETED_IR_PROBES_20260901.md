## FMA 为什么不同于先乘后加
+
+FP32 只能保留有限位数，计算后要舍入。FMA 对 `a*b+c` 最后舍入一次；普通乘法先舍入乘积再加，有时结果不同。原文精确有理数探测得到 FMA 位模式 `0x41473989`，先乘后加为 `0x4147398a`，相差一个最小可表示步长（1 ULP）。
+
+这说明融合约定有独立意义，但还需精确指令、独立来源、特殊数值政策、正反语料和完整目标输出。首个候选范围只有三个 `[1024]` FP32 输入和同形输出，无标量参数、广播、状态、别名或动态长度。
+
+## 余弦为什么不能只加一个名字
+
+cos 输入输出同为固定 `[1024]` FP32，需要先确定后端实现、精度、无穷和 NaN 等行为。数学 API 存在不代表已经知道底层是普通设备函数还是快速近似。两个导数消费者也要先拆开余弦与其他乘除，确认要求一致。
+
+因此该时点停止在精度／指令合同之前，不用词频或模型文字 决定 IR。单写入状态更新另有提案，通用动态形状／索引／控制不能捆成一个“大操作”。后来的设计审查见[2026-09-04 记录](AKA_IR_OWNER_REVIEW_20260904.md)，不会反改此处历史。
