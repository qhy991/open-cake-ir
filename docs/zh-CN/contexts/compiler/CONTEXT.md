# Compiler：检查和翻译执行计划

[中文目录](../../README.md) · [英文原文](../../../contexts/compiler/CONTEXT.md) · [统一术语](../../../GLOSSARY.md#compiler-terms)

把编译器想成一位严格的图纸审查员兼翻译员：按明确硬件规则检查图纸，再把允许的计划翻译成目标源码。这里只解释职责，术语定义由上面的词表负责。

## 负责什么

- 读取完整 Schedule，按一个精确 Target 检查格式、类型和含义。
- 针对计划语义、硬件规则、数据一致性、程序安全和后端生成前提，给出能定位的 Finding。
- 说明分析实际看了哪些内容；估算不能写成 GPU 事实。
- 按确定规则生成可检查源码，或选择唯一允许的已核验固定源码。
- 通过完整 Corpus Gate 和外部批准后，才发布语义变化。

它不负责题目的数学、输入生成、标准答案、AI、实验组织、GPU 分配、评测、证据或研究结论。

## 输入之间怎样关联

一个计划用一个 Compiler Revision，在一个 Target 下检查。Assessment 中有零条或多条诊断，并分别记录结构接受和生成资格。一个发布版固定一套完整语料预期。校准只对绑定的版本和目标范围有效。

Lab 可以使用发布的编译器；编译器不能导入 Lab。

## 别把下一步当作已经完成

“计划接受”不等于“后端允许生成”；允许生成不等于源码已经编译，编译成功也不等于答案正确。目标 `sm_100a` 允许某种指令约定，也不能证明此刻有可用 B200，或另一架构可以套用同一估算。
