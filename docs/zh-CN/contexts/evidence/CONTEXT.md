# Evidence：保存事实，让别人能复查

[中文目录](../../README.md) · [英文原文](../../../contexts/evidence/CONTEXT.md) · [统一术语](../../../GLOSSARY.md#evidence-and-report-terms)

证据系统像只追加的实验记录本：保存实际文件和事件顺序，不替实验改题，也不只留下成功的一页。

## 负责什么

- 保存不可变内容，不沿链接跳出允许的文件保管范围。
- 由一个写入者按顺序追加有类型的事件引用。
- 每个结束的 Run 都产生一种统一的 Terminal Archive，包括失败和偏离规则的 Run。
- 在不调用 AI、GPU、网络、不修改 checkout 的情况下，重建完整性、保管要求、协议遵守和终点观察。
- 对合格 Run Audit 应用预先登记的分析计划，并生成可删除重建的当前视图。

它不判断数学答案，不在实验后重新定义估计目标，也不拿后继规则重解释旧 Run。

## 文件怎样变成报告

Event Ledger 引用 Evidence Object；结束的 Run 对应一个 Terminal Archive。Run Audit 只读保留材料；Study Report 对审计应用固定分析；Claim View 从已接受报告生成。

## 完整和可信保管是两件事

假设一本实验记录每页都在，但无法核实谁在什么时候能改它。可以说内容齐全，却不能证明写入过程符合规则。仓库拷贝同样可能文件完整、保管资格未验证：可以检查，不能据此晋升候选或生成需要可信保管的结论。

AI 服务失败也可能留下完整归档；失败事实会出现在协议或终点字段中。归档完整不等于实验成功。
