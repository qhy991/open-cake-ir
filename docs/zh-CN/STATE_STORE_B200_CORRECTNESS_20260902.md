# 原地状态更新：前四次交接结果与后继准备

**历史系列：2026-09-02，末尾追加 2026-09-06 的 v5 准备。任务 v1–v5 与 Compiler v40/v41 是两种不同编号。**

最终，**任务 v4 在 Compiler v40 上通过四组固定 `[8,128]` 完整输出检查；任务 v5 只是改为绑定 Compiler v41 的准备，GPU 仍待做。** 不能只读英文原文开头第一次失败，也不能把 v4 成绩挪给 v5。

| 任务 | 最早失败或结果 | 结论 |
| --- | --- | --- |
| v1 | broker 无权读候选 judge，没导入／运行 | 基础设施未知 |
| v2 | 到首次计算后，无权写输出和结果 | 没有持久完整输出，未知 |
| v3 | judge 退出 0 并写文件，但 daemon／collector 无权读取 | 节点结果仍基础设施未知 |
| v4 | 读写交接完整、节点收据有效、完整输出可取且独立重算 | 固定实例正确性通过 |
| v5 | 精确绑定 v41 的源码、任务和 CPU 准备 | GPU 未运行 |

这里容易误会：进程退出 0、文件存在，甚至代码可能已经计算，都不能替代可读取、可核对的正式结果。

四组数据是全零、有符号整数、交替二进制小数、固定种子缩放整数。每组 1,024 个状态元素，v4 全部 oracle/state/update 位比较零不符、最大误差 0，update 未改、原状态指针不变、返回空元组。镜像独立检查不导入 judge，而用标准库重建 FP32 并逐项比较。

三个前任在各自身份下保留，权限修复形成不同基础设施后继，没有抹掉旧失败。v4 完成后只清理任务自己的已结束 daemon，保留节点状态和镜像，其他共享服务与 GPU 任务没有改变。

v5 从精确 v41 源码生成并验证来源，后来的 Compiler 会被拒绝并要求新任务后继；v4 可用原 v40 的完整历史提交回放。所有源码、路径、job 与收据定位由原文负责。本系列没有计时、性能、任意长度、完整父项、模型、服务或训练资格。
