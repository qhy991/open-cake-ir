# 补了 FMA 后，十二个完整父项还剩什么问题

[中文目录](README.md) · [英文原始记录](../AKA_FMA_PARENT_REAUDIT_V41_20260906.md)

本页用中文解释原文的背景、决定和结论范围；逐项长表、精确来源及原始记录由链接中的原文负责。

**历史再审：2026-09-06，使用已发布 v41。当前修复另见[后续读取检查](../ACCESS_DOMAIN_REPAIR_20260906.md)。**

十二项原先共同缺少单次舍入 FMA，现在这一个障碍都已解决；完整任务却可能还缺其他能力。

| 结果 | 数量 | 能说明什么 |
| --- | ---: | --- |
| 语义审查后生成并真实离线编译 | 4 | 四个固定实例通过静态和编译，不是 GPU 正确 |
| 仍有计划语义缺口 | 5 | 主要缺按值运行时 FP32 标量和复制到寄存器向量 |
| 独立语义审查拒绝 | 1 | 隐藏标量广播；真实编译另遇三元素向量限制 |
| 写作被拒绝 | 2 | 模型提交非法计划，不能据此认定 IR 缺口 |

这是 `4/12` 固定实例静态与编译存活者的下界，不是全部 AKA 33% 覆盖率。最大五并发之前有通过的单例；模型工具、网络、GPU、子代理禁用。所有结论保留固定实例范围，不追加整个动态接口要求。

五个缺口说明运行时的 momentum、weight_decay、alpha、beta、ratio 等需要真正的按值函数参数。JSON 常数是编写时固定值，把标量改成长度一的指针会改变 ABI；应由独立标量负责人喂给三输入 FMA，不能在 FMA 再藏一套标量字段。

另一个实质缺陷是：v41 允许把只读一个值的 load 声明为 `[128]`，后端悄悄广播，甚至能编译。语义审查拒绝前任，再用逐元素小计划证明某固定父项并非必需新广播操作。还有 `tl.arange(0,3)` 缺少生成前诊断。它们不否定早先三个明确同形向量的 FMA GPU 测试。

两个模型非法计划不事后修补改名；所有失败与规范化边界保留在[十二项数据与尝试索引](../data/aka-fma-v41-reaudit-20260906/)。下一步分别审查四个存活者的 GPU 准入、修 load/向量规则、审标量设计、重新写作两个失败项；log/cos 和性能另做。本次没有提交 GPU。
