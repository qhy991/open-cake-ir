**历史周报：2026-08-24 至 2026-08-28，Asia/Shanghai。包括 Compiler、Lab、B200、AMD 与算子结果。**

这一周的主要变化是形成可复查的循环：计划 → 编译器检查 → B200 判对计时 → NCU 找瓶颈 → 改生成方式 → 新确认 → 必要时纠正静态分析。

| 结果 | 候选与对照绝对时间 | 当时边界 |
| --- | --- | --- |
| QSA tile256 新确认 | 288.210 ms 对 676.407 ms，约 2.34692 倍 | 固定 T=32768 的完整算子 Program；正式 Program 晋升当时暂缓 |
| RoPE 匹配搜索 | 两组中位数 1.511927 ms 对 5.342292 ms，比例 3.53343 | 六个预定 Run 合格且归档的算子层比较 |
| TinyGEMM2、weighted combine、原子保留 | 正确性记录 | 未测性能 |
| AMD gfx1151 分支 | Executor 与静态检查记录 | 编译器独立批准和正式性能任务仍缺前提 |

QSA 初始 Cake 程序约 7,001.505 ms，远慢于约 676.396 ms 的基线，是有效负结果。NCU 指向旧 top-k 的大量展开、寄存器与等待；紧凑生成后先到约 399.121 ms，再由 tile 搜索和新确认得到上表结果。

另一个重要发现是 QSA 的逻辑寄存器压力 140，却实测物理 116，推翻下界解释。因此不能仅凭速度成绩继续扩大搜索，而要先修分析负责边界。NCU 对齐的静态 profile 有界说明精确、下界、上界或未知，不自动授权候选排序。

AMD 当时解决了身份复用冲突，发布独立 gfx1151 v2 的 47 源码 Executor，47/47 Gate、160/160 针对检查，但 Compiler 批准与搜索合同仍未完成，未宣称 AMD 性能。

这些数字只属于该周固定证据和分支；当时源码、远端与分支发布关系见原文。下一步是修寄存器分析、冻结并确认 QSA Program 后继、完成 AMD 审查，再考虑模型接入。QSA 和 RoPE 都不是模型检查点或服务端到端结果。
