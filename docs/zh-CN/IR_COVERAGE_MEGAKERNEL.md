# Megakernel 与 KDA 调查：一个固定计划装不下动态程序

[中文目录](README.md) · [英文原始记录](../IR_COVERAGE_MEGAKERNEL.md)

本页用中文解释原文的背景、决定和结论范围；逐项长表、精确来源及原始记录由链接中的原文负责。

**历史调查：2026-08-24，26 类选择中 1 类当时完整表达。**

普通 Schedule 像一张写好顺序的工单；这里的 megakernel 像一个工厂控制程序，GPU 运行时还会读入下一条工单，多个算子把片上资源交给彼此。它的程序本身就是输入数据。

第一层差异是跨 CTA 同步：所查实现通过全局原子计数等待其他 SM 完成，需要发布顺序、具体生产者／消费者、细粒度计数地址和每 token 重置。原文特意指出该实现不是 `grid.sync` 模型，不能用名字相近的屏障代替。

第二层是跨算子资源：共享内存为 13 个 16 KiB 页组成的池，哪个页先归还影响下个算子；TMEM 一次分配跨多个算子传递；流水线装的甚至是操作描述符、计时和信号量，而不是单个算子的普通数据块。

第三层是动态工作：GPU 读 128 字节指令流，运行次数、角色工作量、信号量到达数都来自数据，注意力分区增加还会创建新操作。工作按 SM 身份分配，不能只用固定 block 坐标说明。

Kimi Delta Attention 另需按运行时索引读写状态池、衰减门控、更新后状态参与输出归约，以及针对小 batch 的专用分工。当时只有状态的 V 方向切块与双缓冲完整对应已有原语；后来的状态与索引能力须看各自后继记录。

结论是当时这种动态解释器与单个固定操作列表的 Schedule 有结构边界，不能加一个 megakernel 标志就声称支持。本页没有给出当前完整性或性能保证。
