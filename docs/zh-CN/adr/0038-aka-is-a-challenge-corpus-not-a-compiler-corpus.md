# ADR 0038：AKA 是发现问题的外部题库，不是正式验收语料

[设计目录](README.md) · [英文原文与完整证据](../../adr/0038-aka-is-a-challenge-corpus-not-a-compiler-corpus.md)

**原文状态：2026-08-28 接受外部题库审查，后附便携父算子审查规则。**

AKA 的一条任务记录可以帮助发现 Cake 描述不了的机制，但不是独立 kernel、标准答案或性能判决。每条分别问“局部改动能否表达”和“完整父程序能否表达”，不能把前者算成后者。

原文固定的 v1 有 1,362 条四字符串记录、142 个分片；排除区的 51 条不在分母。主产物的语法信号为单 kernel 951、多 kernel／启动 398、片段或库包装 13；候选、修复产物另算，不继承父代码分类。关键词只供检索，不能算语义缺口。

v2 当时声称保留 v1，却只有 230 条逐字节相同；没有稳定来源身份解释改写，所以不能直接扩大已准入快照。`aka_v1_operator_sft` 与 `aka_v2_review_projection` 明确选择字段角色，后者的中性／负面审查文本不提取 CUDA 信号。

只读适配器从指定 Git 提交的正常 blob 读内容，拒绝链接、嵌套路径、错误结构与非提交引用；替换引用、未跟踪或修改后的工作区文件不影响结果。它输出去除凭据的来源定位、行号、字段及信号，不复制模型内容、不写 Compiler manifest、不改 AKA。

单 kernel 算术和地址归 Schedule，数学和 oracle 归 Workload，分发归 portfolio，多次启动和流关系归程序组合，来源及数据划分归 AKA，编译和测量归外部评测。框架包装先补出具体语义，才有资格说缺一个 IR 操作。

逐条审查在仓库外创建 case。非 unknown 判断需要完整父算子记录；候选用固定 Compiler 检查，但仍 `semantic_binding=reviewer_claimed`、`gpu_test=not_run`。只固定一个运行实例时使用 `fixed_instance_*`，不能给整个动态合同盖章。

旧队列中 180 个历史合格父项，只有 15 个还拥有有效增强终态；14 个单 kernel 优先审查，另一个去程序职责审查。这是优先级，不是 IR 接受。便携 v1 的 50 条中一条 debug 字段不同，明确要求字段覆盖处理；其余仍只是经父验证器接受的 runnable 记录，节点保管未审。v2 新增 100 条的池按固定提交差集准入、各项独立、不重试，全部普通完成才可报告控制器完成。

进入正式 Corpus 要固定源码、接口、形状、目标和 oracle，先找负责人，再做完整计划或明确缺口；新能力同步更新类型、规则、分析、生成和正反例，通过完整 Gate 与独立发布审查，再取得 GPU 正确性。行频率和模型回答都不能直接授权新操作或性能声明。
