# ADR 0012：每个搜索后算对的候选都要留下瓶颈分析

[设计目录](README.md) · [英文决定与资格记录](../../adr/0012-profile-each-correct-search-survivor.md)

**原文状态：已接受，2026-08-24。**

Study 声明 `correctness_then_profile_each_search_survivor` 后，每个搜索启动通过正确性的候选都要有单独 profiler 收据，包含没被最终选中的候选。错误候选不做这种分析。

```text
筛选 → 搜索候选 → 算对则收集 profiler
     → 按合格搜索时间选择 → 独立确认
     → 下一轮得到选中候选的已保留分析
```

搜索记录说明该次启动是否算对；分析记录保存原始 NCU 及可核对摘要；确认记录负责 Run 终点。profiler 不排序、不贡献普通延迟、不替代确认，也不能用后面记录补前面缺项。

一旦 Study 要求分析，缺失、格式错误或错误启动的分析就是协议故障。回放要求每个正确搜索恰好对应一份分析，其他搜索候选没有这种收据。旧 `correctness_then_profile` 只在旧实验中按“仅分析选中者”的原义回放。

原文 v3 资格中，每边三候选、搜索两个正确者，都分别收集分析并确认选中者；总共十份收据，四份分析各保留 11 项原始数据核对后的指标，不含计时。它仅证明系统关系接通，估计目标、效果和不确定性为空。
