# ADR 0036：只有从原子分配推得唯一位置，才允许普通索引写入

[设计目录](README.md) · [英文原文与完整证据](../../adr/0036-atomic-reservation-proves-indexed-store-ownership.md)

**原文状态：提案，2026-08-25。原文 GPU 验收仍缺失，不能把提案写成已通过。**

“我保证不会撞地址”不能当作证据。已有 store 只有能从 `atomic_rmw(+1)` 的旧值机械推出独占位置，才允许这个首个索引写入形式。

AccessMap 恰好两个运行时坐标：同一原子状态的专家索引，以及该原子返回的旧计数。store 与原子在同一角色、都在 tile 循环外，各 program 各执行一次；必须读取确切索引和结果，不接受别名、变换或手写唯一性标志。通用数据流规则负责先后顺序。

每次加一得到不同 `(专家,旧计数)`。状态与目标专家轴范围一致，位置掩码挡住负数与超容量；静态更新总数不超过 `2^32`，防止返回位模式再次重复。另一写操作不能改同一状态。初始计数接近溢出时，被掩掉的写入不产生冲突，但不保证所有路由完成；完整性需另一个运行合同。

验收分别拒绝无关／颠倒坐标、不同掩码范围、跨角色、非加一、循环重复、过大启动、错误读取顺序与结果形状。正确性 oracle 预先缩小到所有保留位置都放得下的输入，比较写入集合和计数，不要求竞争者顺序。

首次 GPU job 因临时目录权限在 worker 准入停止，没运行 Python、编译或 GPU；未重试。所以原文静态验收已完成，GPU 第五项仍缺失。原子累加 scatter 和按运行时路由度选择普通 store 都不在此提案范围。
