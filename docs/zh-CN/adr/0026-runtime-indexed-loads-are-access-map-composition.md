# ADR 0026：读哪个位置，可以由前面算出的索引决定

[设计目录](README.md) · [英文原文与完整证据](../../adr/0026-runtime-indexed-loads-are-access-map-composition.md)

**原文状态：已接受，2026-08-25。**

普通读取的位置在计划中描述；路由还需要先读出专家号和行号，再去取对应数据。已有 AccessMap 增加一个 `buffer` 索引形式即可，不另加 gather、routing 或 MoE 操作。

索引必须是本操作明确读取的一维寄存器 INT32 Buffer。多个索引长度相同并逐项配对：专家 `[2,5]`、行号 `[1,3]` 取 `(2,1)` 和 `(5,3)`，不是四种交叉组合。这个共同索引维度在结果中只出现一次，再接独立的 tile 或完整维度。

`mask_tiled_axes` 同时检查运行时坐标上下界，越界加载补零，不允许环绕或不检查。初始只支持普通全局 load，TMA 和索引写入在规则未定义前拒绝。

正例八个 token program、各八个路由槽，读取 `[expert_id[slot], row_id[slot], hidden]`，包含 `-1` 哨兵。验收用独立参考核对有效值与补零，并分别拒绝 FP32 索引、未知 Buffer、未声明读取、非寄存器、不同长度和不支持操作。它不证明原子分配、写入冲突或完整 KDA，未作计时声明。
