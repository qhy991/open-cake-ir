# ADR 0038：QSA 需要跨块选择状态和多次启动组合

[设计目录](README.md) · [英文原文与完整证据](../../adr/0038-qsa-needs-stateful-selection-and-launch-composition.md)

**原文状态：提案。只允许实现与准备语料检查；发布、AI 和 GPU 实验分别验收。**

目标是比较固定 `target_t32768` QSA prefill 的完整写作环境，输入从投影之后开始。题目、oracle、目标、测量、模型、推理、参考、预算和停止规则都要匹配；不是模型检查点复现或服务结果。

当时缺四件事：ReLU；跨多个键块保留前 512 项的 top-k 状态；稀疏 GQA 的稳定在线 softmax；把索引／选择与注意力等多个 kernel 放在同一个逻辑接口后面运行。

提案只增加通用能力：在 elementwise 中加 relu；在已有 top-k 中明确跨循环状态、并列、初始化和结束；增加带 FP32 最大值、归一化量、加权值累加状态的 online_softmax。每项同时具备类型、目标准入、定位诊断、工作量分析、生成以及正反语料。

Evaluation 拥有不可变启动计划，写明节点顺序、中间 Buffer、依赖、外部参数和各节点启动说明；每个计划产物保留 Compiler 身份，两种写作环境经过相同整算子判对、计时和 profiler。不能把手写 Triton 冒充 Cake 生成，也不能把索引预计算移出测量范围。

验收顺序是固定任务、语料及单独预期审查、独立发布、共同 B200 评测、冻结匹配 Study、保存每个结果完整来源。慢但有效是负结果，oracle 不符是候选错误，SSH、调度、保管或缺结果是未知。没有投影、RoPE、KV cache、多形状分发、服务或报告中 10.2 倍成绩的声明。
