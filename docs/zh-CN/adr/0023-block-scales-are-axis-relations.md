# ADR 0023：量化缩放系数与数据轴建立明确关系

[设计目录](README.md) · [英文原文与完整证据](../../adr/0023-block-scales-are-axis-relations.md)

**原文状态：已接受，2026-08-25，原文实现于 Compiler v17。**

FP8 数据像用较粗刻度记下的数，还需要缩放系数才能还原。缩放表不是两块毫无关系的数据：每块覆盖多少元素、按哪些轴存放，必须明确。

一个 FP32 缩放 Buffer 的 `scale_of` 写明对应 FP8 Buffer、每轴 `granularity` 和存放轴顺序 `axis_order`。数据轴大小 D、分组宽度 g 对应组数 `ceil(D/g)`，再按轴顺序排列得到缩放形状。例如 `[16,256]` 按 `[1,128]` 分组并交换轴，缩放形状是 `[2,16]`。

分块缩放 MMA 的读取顺序固定为 A、B、A 的系数、B 的系数。加载到片上后，对应关系也要跟着正确迁移；不能靠名字猜。初始 Triton 只处理明确的两个等长、整除 K 块，以及一个 B 的 N 缩放组：各块矩阵乘后分别缩放，再以 FP32 累加。其他可描述关系必须报告 `MMA_BLOCK_SCALE_UNLOWERABLE`，不能悄悄不缩放。

验收分别覆盖形状、数据类型、轴排列、加载传播、输入对应和后端范围。历史 `[M,N,K]=[16,128,256]` 正例在 B200 比较 2,048 个输出，最大误差约 `1.79e-7`，低于 `1e-5`，未计时。没有加入 FP4、打包缩放、动态尺寸、量化操作或完整 KDA 能力。
