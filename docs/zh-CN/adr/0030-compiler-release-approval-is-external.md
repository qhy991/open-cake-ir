# ADR 0030：准备发布的人不能顺便批准自己

[设计目录](README.md) · [英文原文与完整证据](../../adr/0030-compiler-release-approval-is-external.md)

**原文状态：后继发布接受，2026-08-25。现行独立代理要求由 [0052](0052-independent-agent-release-review.md) 补充。**

发布脚本可以计算下一版身份、归档历史并运行完整 Corpus Gate，但不能创建或修改 `compiler/release-approval.json`。外部审查者检查这份具体差异后写批准，再由同一发布路径核验并发布。

Gate 报告是审查对象，批准文件是唯一批准依据，`release_compiler.py` 仍是唯一验证和构建者。先生成并验证临时 lock，成功才替换当前 lock。

缺失、过期或格式错误的批准不产生后继，旧批准与旧 lock 保留；Corpus 不匹配在批准前就停止。旧批准在其发布归档中不可改。

验收在临时 checkout 改一项受版本约束的源码：第一次准备应拒绝旧批准并保留旧文件；只有独立的测试审查步骤写了精确新批准，第二次才可发布。这个边界保证“准备不能自批”，不凭空引入签名服务或追认旧 v24 已获独立审查。
