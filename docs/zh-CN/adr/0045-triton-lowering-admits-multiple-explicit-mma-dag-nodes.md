# ADR 0045：一个计划可以明确写多个 MMA 节点

[设计目录](README.md) · [英文原文与完整证据](../../adr/0045-triton-lowering-admits-multiple-explicit-mma-dag-nodes.md)

**原文状态：提案。**

已有语义能写两个独立矩阵乘法，再加结果，不应被生成器旧的“最多一个 mma”限制挡住。移除这个总数限制，但每个节点仍必须分别检查类型、目标、唯一写入者、后端支持、顺序与依赖。

例如把 K=128 拆成 `[0,64)` 和 `[64,128)` 两个 IEEE FP32 点积，得到两个 FP32 临时值，相加后再做每头 ReLU 和求和。两段覆盖且不重叠，查询和键的切分匹配；不能把两次写隐式当成同一个累加器。循环内累加继续按已有规则，独立部分用赋值。

实数数学相同，却可能因为浮点舍入顺序改变近似并列；仍由原 oracle 和容差判对。两个 MMA 的乘加量相加等于原 K128，但额外加法还要计入工作量。分析逐节点看生命周期，逻辑压力减少不等于物理寄存器或共享内存减少。

验收覆盖第二个节点的错误、两次源码调用、显式加法顺序、工作量与旧单 MMA 不变，再做语料审查和发布。候选之后才精确编译、核对和测完整程序。不得为此改变冻结 Workload、Program、评测器或容差；资源指标变好而整程序没明显变快不能晋升。
