# ADR 0043：FP32 存储可以明确选择 TF32 乘法精度

[设计目录](README.md) · [英文原文与完整证据](../../adr/0043-fp32-mma-may-explicitly-request-tf32.md)

**原文状态：提案。**

数据存在 FP32 数组里，与硬件乘法采用哪种输入精度，是两个事实。已有 `mma` 指令约定增加 `triton.dot.fp32_tf32`，输入、累加和结果仍是 FP32，生成时明确指定 `input_precision="tf32"`。

不能偷偷用默认值，也不能改成 IEEE、TF32x3 或 BF16。`triton.dot.fp32_ieee` 保留为另一种明确选择；不增加 TF32 Buffer 类型或全局精度开关。TF32 输入精度可能改变答案，不能说它与 IEEE 逐位等价。

类型、目标、诊断、工作量、源码生成和 Corpus 必须一起更新；仅在 Target 加一条名字不算可生成。分析保留精确指令选择，不编造延迟、误差、寄存器或共享内存。

验收先分清 FP32-TF32、FP32-IEEE、BF16-FP32 及错误输入／目标，再由精确工具链证明选项被采用。完整 Gate 和外部批准后，候选还需通过未放宽的 oracle，再测匹配的完整程序。编译失败属工具链未知，算错是无效候选，正确但改进不足是负性能结果，均不能冒充服务收益。
