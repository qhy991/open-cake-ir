# ADR 0020：用 KDA 历史找缺口，分清局部机制和完整程序

[设计目录](README.md) · [英文原文与完整证据](../../adr/0020-kda-deltas-are-an-external-expressibility-corpus.md)

**原文状态：已接受，2026-08-24。这里的数字属于当时固定的 57 版历史。**

检查外部 KDA 要问两件事：相邻版本改变的机制能否表达？那一版的完整程序能否表达？能调整一颗螺丝，不代表能造出整辆车。原文快照完整版本覆盖是 `0/57`，不能拿后来的一个调优参数冒充完整支持。

每个 kernel 内的数学、依赖、放置和资源归 Schedule；固定形状专用方案选择归它上方的 portfolio；CUDA Graph、流顺序、PDL 等跨 kernel 关系归程序组合；正确性、计时、NCU 等历史结果仍归 KDA。

56 次 judge 通过和一次 v3 失败只是外部历史。持久取任务、数学归约、分布式共享内存与 scatter、数据复用、流水线生命周期、跨 kernel 调度等变化要按机制归类，不建立 57 个模式或复制测量账本。

最先选 `tanh`，因为多个独立变化重复用到它。先做独立 SwiGLU 正例、形状反例和 B200 外部判对；这证明基本操作，不证明近似指令等价或完整 MoE。后来的 top-k、缩放关系、有效范围和分组矩阵乘法分别补自己的边界。新 KDA 版本要另做后继审查，不能扩大旧快照。
