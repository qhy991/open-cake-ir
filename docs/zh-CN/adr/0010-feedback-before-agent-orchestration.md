# ADR 0010：先证明反馈有用，再考虑增加管理代理

[设计目录](README.md) · [英文决定与历史观察](../../adr/0010-feedback-before-agent-orchestration.md)

**原文状态：已接受，2026-08-24；另附 2026-08-25 参考审查。**

当时虽然开放了丰富工具，但两次尝试第一轮就越过 token 检查点，没有得到评测反馈，也没有出现辅助代理活动。此时加“经理”只会增加调用、状态和用量记录，解决不了已经观察到的问题。

先在原路径做有界两轮产物优化，第二轮只接收 Lab 保留的构建、测量和瓶颈反馈。终点 token 检查点与最大轮数一起明确，只适用于工程产物优化；不能据此改变系统资格或科学 Study。轮数是调用硬上限，轮末超过 token 边界不能倒填检查点。

原文 v4 中，两边都完成同一会话两轮。Cake 自身确认延迟从 `1.851297 ms` 改进为 `1.417239 ms`；CUDA 从 `4.156109 ms` 退步到 `8.814379 ms`，所以正确保留第一轮。没有辅助代理事件；这证明反馈和角色分离，不能证明多代理效果或两组科学差异。

未来若反复出现现有反馈无法表达的方向选择，才考虑独立只读管理调用。它只能选有限的方向、不提供实现、不用 GPU，并保存输出和 token。KDA 参考中的 `neutral/explore/exploit/recover` 是可研究做法，未因此成为本项目的新字段、模式或运行依赖。
