# ADR 0008：没有合格校准，就不能假装会排序

[设计目录](README.md) · [英文决定与旧测量](../../adr/0008-calibration-coverage-gates-ranking.md)

估算规则像一把尺子，必须先证明在这类题目上够准。发布 lock 中的 `calibration_coverage` 是唯一的覆盖依据。`assess` 把它投影成 `calibration_available`，公开排序复查 Assessment 后才使用这一事实。

没有覆盖时，本来可以生成代码的计划进入暂不排序集合；被规则拒绝的计划仍保留拒绝理由。调用方保有完整候选，可按作者原顺序使用 GPU 预算。内部排序函数即使结果稳定，也不能把未校准范围变成已校准范围。

跨版本或字段与重放不一致的 Assessment 会被拒绝。新增覆盖只能进入后续审查通过的发布，并明确有效输入范围和固定测量协议。

原文历史扫描中，Flash-KMeans 的最佳项选择损失为 `19.43%`，GEMM 为 `1.72%`。后者看起来小，但未经事先登记的单次扫描不能事后定义门槛再宣布通过，且语义并列尚未解决。因此两者都没有授予发布覆盖。此决定不预测时间、不增加排序项，也不自动晋升校准。
