# ADR 0018：并列就不强行淘汰，测量要控制时间漂移

[设计目录](README.md) · [英文决定与校准结果](../../adr/0018-ranking-is-a-preorder-and-calibration-controls-drift.md)

如果两个方案的有效性能依据相同，按名字字母顺序挑一个，并不算性能判断。`Cost.order` 先比较设备填充，再看驻留上限；`schedule_id` 只让输出次序稳定。`rank_for_cut` 若在并列组中截断，就放弃决定。

这次校准仍只研究固定 GEMM `M=512` 的三选二，损失门槛仍是 `5%`。旧 v7 计划写错展示身份，检查器在核对依据时就拒绝，不能评价性能；v8 只纠正该拼写后重新测量。

旧逐个候选连续计时可能把“程序差异”与“恰好当时机器状态不同”混在一起。后继先编译并判对全部候选，再做 50 轮，每轮每个候选测一次并循环轮换位置；预期 25 个候选各在每个位置出现两次，其他输入、冷 L2 和独占 B200 条件固定。

检查器在看性能前划分全部子集：每轮 `1,450` 个能明确截断，`850` 个因并列放弃。最坏损失 `5.73%`、`2.79%`，第一轮仍超过门槛，所以校准失败，原文 Compiler v11 仍无覆盖。

去掉名称决定修好了一个语义问题，却没有证明结构填充指标足够安全。错误、缺项、来源不符、重复测量或超过门槛仍全部拒绝；旧负结果保留。即使将来通过，也只能发布精确已测范围，遇到并列要保留作者顺序。
