# ADR 0033：TinyGEMM2 的真实输入字节由 Workload 负责

[设计目录](README.md) · [英文原文与完整证据](../../adr/0033-workload-materialization-owns-tinygemm2-input-bytes.md)

**原文状态：已接受，2026-08-25。其未使用身份处理方式后来受 [0049](0049-released-executor-descriptors-reserve-their-identities.md) 进一步约束。**

只写随机种子不一定能重现相同数据。旧 v1 来源说输入和权重除以 8，但任务记录没有真正固定这一步。v2 用输入、权重、偏置、独立 FP32 线性计算后转 BF16 的参考，以及历史父输出，共五份 materialized 收据明确字节。

种子、模式和生成代码只是复现方法，不能覆盖收据不符。前四份要由一次预先登记、零重试的历史生成器 B200 重建，与保留结果完全相同后采用；第五份是旧父输出，不能冒充新启动观察。

v2 是当前评测入口，v1 只保留供历史检查。缺收据、字节或大小不同、非 CUDA 生成，都在候选启动前拒绝；CPU 或单位正态生成不能代替原分布。适配器变化需要后继 Executor，Compiler 不变。

输入相同是下一次正确性检查的必要条件，并不证明固定源码算对。以后真正启动仍要同时验证父输出逐位相等与 FP32 oracle 容差。此决定不复制旧运行器，也不把摘要一致当作 GPU 正确性。
