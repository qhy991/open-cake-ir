# ADR 0024：固定容量里，有效长度可以运行时给出

[设计目录](README.md) · [英文原文与完整证据](../../adr/0024-runtime-valid-extents-are-buffer-relations.md)

**原文状态：2026-08-25 在 Compiler v19 接受。**

有四个容量各为八行的盒子，实际装了 `[0,3,8,5]` 行。容量固定，但每盒有效长度存在 GPU 上的 `counts`，无需为读取长度先回到 CPU。

全局 Buffer 的 `valid_extent` 声明哪个维度是有效前缀、长度来自哪个 INT32 输入、用哪些数据轴索引长度。对 `[4,8,16]`，`dimension=1`、`indexed_by=[0]` 要求长度形状为 `[4]`。有效区间是 `[0,length)`；索引轴不能重复、越界或包含被截断维度，长度来源不能自指，也不能是非全局输入。

AccessMap 仍独自决定坐标。生成器从它取得组坐标，读 `counts[group]`，合并有效长度和普通静态边界。无效加载位置补零，形成稠密片上块，因此片上目标不继续带该关系。负长度或超容量长度仍受普通内存边界保护；合法运行值分布由 Workload 负责。

初始后端只支持一个标量 program 轴索引一个有效长度轴，其他组合在生成前拒绝。历史正例覆盖空、部分、满组，B200 的 512 个输出零偏差，未测性能。

这不是动态张量类型、任务调度器、原子计数、分组 GEMM、scatter 或跨 kernel 程序。不能仅凭 `counts` 名字推断不等长语义。
