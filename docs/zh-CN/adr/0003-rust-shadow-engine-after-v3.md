# ADR 0003：如果改用 Rust，先做结果一致的影子实现

[设计目录](README.md) · [英文提案](../../adr/0003-rust-shadow-engine-after-v3.md)

**原文状态：提案，2026-08-22；文中的 v3、v4 是当时的计划，不是当前版本。**

当时 Python 已能处理计划、检查和生成代码，语义还在发展。立刻换语言可能把尚未定型的规则固定下来，也没有证据说明解析速度已经成为瓶颈。

提案建议先稳定 Python 编译器，再让 Rust 在相同的 `load`、`assess`、`lower`、`check-corpus` 和发布核验接口后面作影子运行。它要重现诊断顺序、代码与位置、检查字段、生成字节、源码映射、工具链要求及规范化 JSON。对应源码、依赖锁、工具链、目标和语料一起成为新版本内容。

只有差分一致性、完整 Corpus Gate 和外部审查通过，才能切换正式负责者。过渡适配器可以保留 Lab 接口；切换后删除旧语义实现，避免两份规则长期漂移。

Rust 的理由是类型安全、分发和嵌入能力，不能假定它会使 GPU 计算变快。旧实验仍绑定 Python 旧版。如果未来核心变成 MLIR/LLVM 编译过程，应重新评估这个语言选择。
