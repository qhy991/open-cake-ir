# ADR 0007：每个候选和发布版本都要认得准

[设计目录](README.md) · [英文决定与身份冲突记录](../../adr/0007-candidate-evidence-and-revision-witnesses.md)

一轮交多个程序后，只记录“第几轮”就不够了。每个候选必须从提交、筛选、搜索、选择、确认到回放都能对应起来；同一个发布身份也不能代表两份不同内容。

候选按轮次和内容身份识别，评测再加 `purpose` 区分用途。完整筛选顺序归 `candidate_set_filtered`，选择与诊断对象归 `candidate_selected`。先看是否有合格搜索收据，再取最低延迟，并列按筛选顺序。下一轮反馈必须来自选中的同一个候选。

若没有合格结果，第一个被搜索候选可以作为诊断对象，但不能获得检查点延迟或确认胜出资格。回放要重建全部候选、可启动产物、收据与选择；重复、遗漏、选择不符或拿未提交候选参赛都必须拒绝。

发布检查要看所有已声明的冻结引用，不能每个脚本只看自己方便的一小部分。原文记录的旧 v4 身份冲突保留为历史损坏，不能就地抹平；被其他冻结观察占用的名字也不能抢用。进一步的发布身份保留规则见 [0049](0049-released-executor-descriptors-reserve-their-identities.md)、[0050](0050-released-compiler-locks-reserve-their-identities.md)。

此决定取代 0005 的近期搬迁承诺：现有消费者已经引用发布路径，身份修复时不同时搬目录。历史单候选记录只通过有界兼容读取，不新增第二套写入方式，也不产生新 GPU 结论。
