# ADR 0051：load 的结果形状必须符合地址实际读出的范围

[设计目录](README.md) · [英文原文与完整证据](../../adr/0051-load-values-follow-the-access-domain.md)

**原文状态：2026-09-06 已接受。**

从表格只读 `a[batch,batch]` 得到一个数，不能直接宣称它是一排 128 个数。v41 FMA 再审暴露这类错误，旁边还发现非法三元素向量、越界维度导致异常，以及用八元素坐标访问四元素维度未被拒绝。

已有 AccessMap 检查器现在核对直接全局到寄存器 load 的结果秩；全标量地址使用规范 `[1]`。同秩大小与逐项运行索引仍由原规则负责。未知引用给定位 Finding，不抛 IndexError；dimension 坐标必须落在真正访问的维度内。没有加入复制标量、reshape 或布局新概念。

Triton preflight 负责 program tile、loop tile、dimension 遍历生成 arange 的限制。原文所核对实现检查的是跨度，不是要求每个端点各自是二次幂；合法非零起点跨度，以及对非二次幂全局数组使用掩码 tile，要保留。

验收保留原 72 项语料，新增一个标量加载控制和四个复现反例，不重生成旧预期掩盖变化。旧 12 父项报告仍是 v41 历史证据，这次修复不能倒改它，也不产生 GPU 正确性。
