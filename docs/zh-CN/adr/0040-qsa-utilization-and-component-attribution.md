# ADR 0040：QSA 利用率看完整程序，并说明分母来自哪里

[设计目录](README.md) · [英文原文与完整证据](../../adr/0040-qsa-utilization-and-component-attribution.md)

**原文状态：接受于当时已授权的持续工程优化。后继分析修正见 [0046](0046-dynamic-loop-stop-owns-whole-grid-work.md)。**

原目标是固定 B200 上整个五节点 QSA 程序至少达到 70% MFU 或 BWU。程序从投影后输入到 BF16 输出，经过 pool、layernorm、score/top-k、expand、selected causal GQA，不能只挑最快的一个 kernel 百分比。

原文要求用实际微基准测带宽、BF16 矩阵乘及关闭 TF32 的 IEEE FP32 参考速率；独占测量保留原始样本，先过 5% CV。主成绩是平衡候选／基线的冷 L2 CUPTI、无 Graph、无 profiler 的完整程序时间，并保持原正确性与 5% 最小改进门槛。

MFU 把各节点计算量除以匹配速率再求和，与完整时间相比；BWU 用字节量除以带宽和时间，但非精确流量只能给相应界限。后来 0046 进一步说明：微基准参考不是设备理论上限，不能直接拿它宣称严格时间下界。阅读原式必须带上这个修正。

组件诊断按依赖顺序用 CUDA event 记录节点及全程序，节点间不加设备同步，保留原始样本，但不替代主计时。NCU 百分比也不独自证明 70%。

一次只改一个机制，优先减少工作、中间字节和启动；同类资源拒绝重复三次就关闭分支，除非新机制改变理由。正确但小于门槛的改进保留为无显著改进，不替换最好方案。所有结局追加保留，未声明模型、任意形状或服务收益。
