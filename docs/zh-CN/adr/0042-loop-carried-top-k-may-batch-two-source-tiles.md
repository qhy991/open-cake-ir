# ADR 0042：跨循环 top-k 可以每两个来源块合并一次

[设计目录](README.md) · [英文原文与完整证据](../../adr/0042-loop-carried-top-k-may-batch-two-source-tiles.md)

**原文状态：提案。**

如果每次完整合并很贵，而放两个来源块也没增大合并宽度，暂存第一块、第二块到来再合并可能省工作。QSA 的来源 128、k=512 是动机，但速度提升仍是假设。

已有 top-k 增加 `source_tiles_per_merge`：省略表示一次一块，只允许显式值 `2`；显式 `1` 是重复拼写，其他值不支持。它只改变这个操作更新状态的节奏，所以放在 TopKParameters，不放进整个循环的选项。

只允许 FP32、`across_loop=true`。两块合并后仍得到全部有效来源的确定 top-k；同值按全局原位置，正负零等价，NaN 拒绝。奇数最后一块要单独冲刷，部分尾块按有效 stop 遮住，零次循环保留原哨兵。循环内其他操作不能读尚未完成的一对结果。

分析必须展示节奏、批量大小、合并宽度、次数和待处理元素；初始打包临时状态每来源元素 8 字节，来源 128 就是 1,024 字节逻辑量，物理存储仍未知。初始后端要求不展开、不 warp specialize、不 flatten，不能静默抹掉选项。

验收从解析与定位反例，到奇数正例、单独预期审查、完整 Gate、发布，再覆盖零／奇／偶／部分尾部 GPU 判对。实测还要证明第一块确实没做昂贵合并；源码看起来有条件不等于运行省了工作。
