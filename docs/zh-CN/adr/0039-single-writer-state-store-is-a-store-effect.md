# ADR 0039：单写入者的原地更新使用已有 store

[设计目录](README.md) · [英文原文与完整证据](../../adr/0039-single-writer-state-store-is-a-store-effect.md)

**原文状态：2026-09-01 的后继编译器提案。后续实验结果另看各自报告。**

调用者交来的状态要在原位置修改，复制到新输出会改变接口。已有 `state` 和 store 足够；缺的是检查器能证明各个 program 写不同区域的规则。

首个范围只允许直接静态写入：用 ProgramMap，store 在所有 TileLoop 外；每个 program 轴在目标地址恰好出现一次，并且由同一状态 Buffer、同一目标维度拥有；标量 program 轴 tile 为 1，program_tile 按声明宽度；其余维度完整覆盖一次；不用运行时 Buffer 索引或 loop_tile。已有规则继续检查读写、类型、顺序和精确后端。

这像把一张表切成互不重叠的块，每组只改自己的块。等形状的另一个输入不能冒充状态的负责人。只有原地状态更新时可以没有普通输出，host 返回空元组，调用者观察原状态；既无输出也无状态的计划拒绝。

AKA 多个例子只提供真实需求压力，仍是审查者声称的语义、未跑 GPU。不能把任意间接索引、冲突写入、跨 CTA 归约、别名、循环内写入或局部片段带入这个提案。

验收需有 `state=state+update` 正例、漏用 program 轴和错归其他 Buffer 的反例、定位安全诊断、确定生成、完整语料和独立发布批准。完整 GPU 输出另行判对，作者不能写发布批准。
