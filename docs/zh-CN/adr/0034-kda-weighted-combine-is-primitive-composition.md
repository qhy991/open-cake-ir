# ADR 0034：KDA 加权合并使用已有操作组合

[设计目录](README.md) · [英文原文与完整证据](../../adr/0034-kda-weighted-combine-is-primitive-composition.md)

**原文状态：已接受，2026-08-25。**

多个专家各给一个结果，按路由权重相乘再相加，就是此处合并的算术主体。用运行时索引加载、`elementwise(mul)`、`reduce(sum)` 和普通 store 即可，不增加 combine、scatter、cast 或 MoE 操作。

一份例子读取八个专家号、行号和 FP32 权重，从 BF16 专家结果取 `[8,16]` 数据，沿八条路由加权，FP32 求和后写 BF16 `[16]`。`-1` 等非法路由按已有规则读成零。

Buffer 数据类型声明数值规则：相同类型二元运算保留类型，FP32 与 BF16/FP16 混合产生 FP32；其他混合对拒绝。sum/max 归约产生 FP32，最终 store 可保持类型或从 FP32 收窄到 BF16/FP16。把加权中间值误写成 BF16 必须在生成前拒绝。

最初缺 Torch 的尝试和后来结果写出前缺 Cutlass 元数据的尝试都保留为失败。完成运行前准备的第二后继在 B200 一次编译启动，128 个 BF16 输出零偏差、无计时。它仅证明算术主体，未包含路由、分配、两次 GEMM、原子融合 scatter 或持久工作区重置。
