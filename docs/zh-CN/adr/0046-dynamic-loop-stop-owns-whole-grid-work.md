# ADR 0046：动态停止条件决定整个网格实际做多少工作

[设计目录](README.md) · [英文原文与完整证据](../../adr/0046-dynamic-loop-stop-owns-whole-grid-work.md)

**原文状态：已授权后继编译器的提案；未因此完成性能目标。**

如果每个 program 只循环到自己的 stop，却按最大长度给每个 program 计数，会高估工作量，不能叫保守下界。

`work.py` 统一按生成语义计算：program 坐标 → 加偏移 → 整除 → 限制到 `[0,extent]` → 按 tile 宽度向上取整。再乘其他 program 轴的数量及外层静态循环。循环外操作每个 program 执行一次。一次操作链含多个动态 stop 的未建模组合报告 unknown，不退回最大值。

Top-k 合并节奏也读取同一计数来源。不能数的操作列入 `uncounted_arithmetic`，已知部分才可叫下界。只有与设备规格上限比较，才能由精确或下界计算量推出时间下界；微基准速率只是比较参考。流量还要求精确范围，局部地址字节不能冒充全程序实际流量。

原文固定 T=32768：tile128 全网格循环 1,064,768 次，计入 FLOPs 281,303,187,456；tile256 为 540,576 次、285,631,709,184 FLOPs。旧 tile256 多算约 1.94 倍。`cast_query` 仍未计入，所以修正后还是下界。

验收覆盖钳制、零／部分前缀、其他轴倍数、静态嵌套、未知组合、各分析一致与全部旧生成不变。这不改变 IR、判定、生成或测量。缺目标 peak、精确流量和匹配精度依据时，正式 MFU/BWU 仍 unknown，不能借修正宣布 70%。
