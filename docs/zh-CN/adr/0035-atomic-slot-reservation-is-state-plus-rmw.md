# ADR 0035：用调用者状态和原子加法分配唯一位置

[设计目录](README.md) · [英文原文与完整证据](../../adr/0035-atomic-slot-reservation-is-state-plus-rmw.md)

**原文状态：已接受，2026-08-25。**

几个人同时领号码，必须保证每人领到不同旧号码。用调用者提供的全局 `state` 计数器和一个 `atomic_rmw` 读改写操作即可，不新增 slot、counter 或 routing 操作。

初始形式是 INT32 原子加一个显式标量，返回修改前的值，顺序为 `relaxed`、范围为 `device`。state 必须既读又写；AccessMap 独自拥有地址。读序是目标再索引，写序是同一目标再寄存器结果。索引越界不修改内存，返回零；路由的非法标记还得单独保留。

Triton 需要精确目标约定 `triton.atomic_add.i32.relaxed.gpu`。其他类型、顺序、范围或放置在生成前拒绝。

示例从非零计数开始，多个 program 争同一专家，且含 `-1`。宽松原子不保证谁先领号，判对就检查每个专家得到的位置恰好是原计数起的一段连续整数的某种排列，以及最终计数增量正确，不能编造线程顺序。原文 B200 一次启动满足 64 个竞争输出，无计时。

这仅证明位置保留；后续普通索引写入仍需独立的无冲突证明，不代表完整路由或 KDA。
