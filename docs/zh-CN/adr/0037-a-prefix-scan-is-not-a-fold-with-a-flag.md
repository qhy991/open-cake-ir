# ADR 0037：前缀和要保留每一步，不能冒充总和

[设计目录](README.md) · [英文原文与完整证据](../../adr/0037-a-prefix-scan-is-not-a-fold-with-a-flag.md)

**原文状态：2026-08-27 对 Compiler v29 接受。**

`[2,3,4]` 的求和是 `9`，前缀和是 `[2,5,9]`。reduce 消掉一条轴，scan 保留该轴，所以不能给 reduce 加一个布尔开关来混合两种结果形状。逐元素运算也无法凭空产生跨元素前缀。

SCAN 初始只支持 `sum`，方向可正向或反向，两者都能映射到 `tl.cumsum`。没有独立 exclusive 开关；不含当前项的前缀可用包含当前项的 scan 再减原输入表达。

初始只支持 tile 循环外。跨块前缀要携带前面块的总和，不能每块重启后假装是完整前缀。原文也明确记录：当时循环内的阻止部分依赖后端表和别的生命周期规则，是“借来的阻止”，还缺自己的定位检查，不能夸成完整覆盖。

正向和反向 B200 例子各比较 65,536 个输出，零偏差，反例把结果轴删掉，以 `SCAN_SHAPE_MISMATCH` 拒绝。KDA gate 在 scan 之前还需要每头运行时标量的运算；本例输入已算好的 gate 值，所以只证明前缀，未证明整个 gate 阶段。
